# 신규 10종 엔진 구현 기록

기준은 `docs/roster10-spec.md`이며, 런타임 정의는 `packages/engine/src/abilities/roster10.js`다. `emoji-141`~`emoji-150`의 기존 역할·타입 factory를 유지하고, 신규 기본 HP·속도·반경만 패치 전 데이터로 동결했다. 기존 77종의 정의를 복사해 다시 배율을 곱하지 않는다.

## 동결 기본값

표본은 `tests/baseline/content.json`의 같은 등급과 `basic.close` 역할이다. 유효 `isTankAbility`가 참인 캐릭터, `GIANT` sub, `sizeMult>=2.5` 거대형을 제외했다. 각 열의 중앙값을 독립적으로 구한 후 명시 상수 `ROSTER10_BASES`에 저장했다. F 근접은 비누(`emoji-054`) 하나가 비탱커 표본이므로 그 등급/역할의 유효 factory 값을 사용한다. 신규 캐릭터는 다른 신규 캐릭터를 표본으로 삼지 않는다.

`stats.finalBaseHp`는 레거시 타입·역할·개별 override와 최종 1.15 배율 이후 적용한다. 그 다음 B/C 1.06을 한 번 적용하고, 모드 HP 및 성장 배율을 적용한다. 속도와 반경은 기존 stats override에서 고정한다. 아래 HP는 개인전 레벨 1·무증강 값이며, 속도는 Participant 기본 speed 필드다. 실제 입력 이동 속도에는 기존 인간 조작 및 상황 배율이 계속 적용된다.

## 재사용과 최소 확장

- **공통 수명:** 기존 `R.entity`, context, owner/life/cast ID, 정리·교체·취소, SHOT_SPAWN/END 및 EVENT_BATCH 경로를 사용한다. 별도 타이머나 참가자/Peer를 추가하지 않는다.
- **조커:** 최대 240의 swept 안전 착지를 기존 warp sequence에 연결한다. 새 벽 통과·매복·무적 없이 은신 72틱, 분신 300틱/HP 25%/동시 1개다. 실제 평타·새 유효 스킬·양수 피해에서만 은신이 해제된다. 신규 은신 도착 좌표를 공개 FX로 송신하지 않는다. 분신은 기존 피격 가능한 설치물 공간 인덱스를 사용하며 이름/HP/이모지를 별도 ID로 표시한다. 상대의 연막 가시성을 snapshot과 이벤트 모두 적용하고, 소유자·아군·교사는 유지한다.
- **마운틴 팀:** head 속도 36, 범위 800의 첫 접촉을 고정한다. 벽·상자·포탑·버섯·아군/적 플레이어에 걸리고, 시전자만 속도 32로 이동한다. 같은 무공격 travel helper를 외계인(260/26), 찍찍이(180/22)에 사용한다. `R.hit(0)`을 호출하지 않는다. 도착은 벽 표면에서 자신의 반경+1, 플레이어 표면에서 자신의 반경+2 안전 여백이다. 이동 중 앵커를 추적하지 않고 사라진 앵커/기절/강제 이동/사망을 취소한다.
- **왕:** 420/24 돌진의 최초 적에게 계수 60 한 번, 추가 CC/밀침 없음. 반경 260~360/두께 24의 링을 고정 16개 겹친 사각 collider로 만든다. 정확히 300틱, 소유자당 1개다. 생성 전 몸체의 안/밖을 유지하는 분리를 모든 최종 위치끼리 원자적으로 검사한다. 실패하면 벽만 만들지 않는다. 기존 벽/링과 교차해도 16개 전체가 설치되거나 전부 실패한다.
- **임시 obstacle:** static wall 순서와 movingWalls index를 유지한 채 dynamic ID 조각만 추가/제거한다. 생성/제거 때 revision과 기존 collision/grid 캐시만 갱신한다. STATIC_STATE에는 임시 벽을 넣지 않는다. `dynamicWalls={revision,walls,rings}` snapshot을 이동 예측·조준·렌더가 공유하며, FULL_STATE도 같은 현재 수명 자료를 받는다. 기존 77종만 있고 링이 없는 방에는 이 추가 payload 자체를 보내지 않는다.
- **버섯:** HP 20, 감지 26, 준비 30틱 이후 1200틱 대기, 동시 3개다. 실제 적의 이전→현재 선분을 공간 후보로 검사한다. 폭발 95/계수 20, 독 90/계수 4는 기존 피해 경로를 사용하고 CC는 없다. 독은 180틱의 30/60/90/120/150/180에만 처리하며 2개 cap, 같은 소유자/대상/틱에는 가장 큰 한 건만 적용한다. 제거·대체·만료는 폭발하지 않는다.
- **버프:** 기존 moveHaste/basicHaste/shield/heal과 다음 기본 행동 snapshot을 재사용한다. 부캉이 300틱(1.2/1.25), 도깨비 180틱(HP 15% 실드/공속 1.2), 꿀꿀이 180틱(이속 1.2), 푸바오 회복 10% 및 360틱 대기 1.5배 충전이다. 신규 고정 창만 duration=1인 context로 처리하며 기존 캐릭터 duration은 그대로다. 회복·실드 restore와 쿨감은 기존 정책대로 한 번 적용한다. 새 무피해/고정창 능력에 무의미한 damage/count/duration capability를 주지 않는다.

## 실행한 집중 검사

`node --test tests/roster10/engine.test.mjs`: **22/22 PASS**, 해당 시점 런타임 변경 후 451.90ms. 뒤이어 표시용 `roster10Move` 시작/만료 단언을 추가해 해당 고정 버프 3건만 선택 재실행했다(**3/3 PASS, 180.80ms**).

실제 브라우저 통합 검사에서 상대/교사에는 보이는 짧은 밧줄이 본인에게 안 보이는 문제가 재현됐다. 원인은 `Timeline.frame`이 자기 캐릭터에는 최신 tick을 사용하면서 밧줄은 원격 보간용 과거 snapshot 목록에서 찾았기 때문이다. 신규 소유 엔티티 5종만 최신 권위 snapshot에서 표시하도록 수정했고, 기존 77종 탄/원격 보간은 유지했다. 세 snapshot 사이에 짧게 나타나는 밧줄의 spawn/seenInSnapshot/terminal 순서를 재현한 **1/1 PASS, 152.34ms** 검사를 추가했다. 현재 엔진 파일의 검사 수는 23건이며, 이 수정 뒤 무관한 이전 22건을 반복해 실행했다고 기록하지 않는다. 브라우저 재검사는 상위 통합 기록을 따른다.

내용: 동결 stats/기본 타입/capability/aim, 조커 수명·교체·은신·연막·보상 없음, 무공격 대시 거리·벽·취소, 밧줄 적/아군/벽/상자/포탑/실패/앵커 소멸/정확한 표면 간격, 왕 128방향 얇은 ray와 몸체 충돌·정확한 만료·static index·snapshot/prediction revision·원자 분리 실패, 버섯 swept trigger·준비·아군 제외·6회 독·중첩·cap·파괴 무폭발, 고정 버프/힐/평타 charge 소비·거부·다중 대상·만료.

명세 T10.D는 테스트 전용 같은 캐릭터 30명 fixture로 실행했다. 30링=480조각의 생성/교체/정리, 30분신과 실제 참가자 30명 유지, 소유자 30명의 버섯90+독60 동시 유지, 밧줄30개 동시 비행/이동/취소를 단언한다. 자연 만료·소유자 death/life/leave 및 destroy 후 잔존 엔티티/벽이 없는 것을 검사한다. 실제 배정 중복 정책은 변경하지 않는다.

관련 기존 `tests/unit/aim.test.mjs`, `tests/unit/prediction.test.mjs` 4건 PASS. 마지막 관련 경로 합동 실행은 당시 엔진 21건을 포함해 25건/475.77ms였다. 이후 신규 연막/표시 필드 변경 때문에 이 무관한 이동 suite를 처음부터 반복하지 않았다.

별도 `tests/roster10/interaction.test.mjs`는 실제 native 평타/투사체로 분신·버섯을 때리는 경로, native 탄/관통/반사/기존 beam과 링, 교차 링의 독립 삭제, 버섯·heal 상자 밧줄, 10종 death→KEEP/reroll을 실제 `stepWorld`로 검사한다. 기록된 13/13 PASS 실행은 529ms다. 실제 WebSocket ACTION/INPUT·resume·rematch·브라우저 표시 검사는 상위 통합 검사 결과를 별도로 참조한다.

## 검증의 한계

이 문서의 빠른 결정적 엔진 검사는 실물 태블릿, 학교 Wi-Fi, AWS 부하 성공을 뜻하지 않는다. 600초 혼합 점령/후반 동시 클라이언트 성능, Canvas/Pixi 실제 화면, CI 및 최종 SHA는 상위 실행 보고서가 별도 기록한다. PR #8의 기존 30인 연장체력 극한 실패와 실물 기기 미검증은 이 단위 검사로 해소됐다고 표시하지 않는다. 운영 AWS·Pages·Firebase는 변경하지 않았다.
