# 교실 공지와 전체 관전 화면 검증

Windows의 실제 Edge 브라우저에서 로컬 WebSocket 서버에 교사 브라우저 1개, 학생 브라우저 1개, 가상 학생 3명을 연결했다. 두 렌더러에서 각각 개인전과 2·3·4팀 점령전을 같은 방에서 진행했다. 뷰포트는 1280×720, 1024×768, 390×844이며 음악 패널 표시와 숨김을 모두 검사했다. 전체 48개 장면의 좌표·줌·HUD 범위는 [measurements.json](measurements.json)에 있다.

| 실행 | Canvas | Pixi |
|---|---:|---:|
| main `d28b2d8` 화면 기록 | 27.780초 | 29.105초 |
| v34 작업본 기능 검사 | 31.125초 | 32.622초 |

개인전에서 링 중심을 (800,120)으로 놓고 네 참가자를 모두 오른쪽으로 모았다. 1280×720 Pixi의 카메라 중심은 기존 (1546.54,244.54)에서 (800,120)으로 바뀌었다. 390×844의 4팀 점령전에서 음악 패널을 표시했을 때 실제 HUD 사이의 중앙은 y=450.89px였다. 기존 카메라의 y=461px가 v34에서 450.89px로 맞춰졌고, 지형 경계와 베이스가 가용 화면 안에 있었다.

교사·학생이 실제 전투 보급 예고와 180틱 뒤의 획득을 수신했다. 경쟁 학생의 소켓에서도 획득자의 공개 버프 아이콘 상태를 확인했다. 최초 처치 후 양쪽 화면의 공지 높이는 32px였으며 체력·미니맵·입력 버튼과 겹친 영역은 없었다. 새로고침 복구 후 기존 처치 공지가 다시 뜨지 않았고, 새 경기에서 공지 번호가 초기화됐다. [학생의 실제 첫 처치 공지](student-first-blood.png)

초기 집중 검사 18개가 통과하고 환경 피해 테스트 1개가 실패했다. 테스트가 환경 피해에 평타 플래그를 함께 전달한 것이 원인이었다. 실제 환경 피해 문맥으로 수정한 뒤 집중 검사를 통과했다. 추가 단언을 포함한 최종 단위검사 9개는 0.965초에 통과했다. 세 모드의 실제 체력 감소·사망, 같은 프레임의 두 처치, 팀전 부활 뒤 누적 킬, 10건 연속 공지와 우선순위, 재접속 기준점, 전송 보류 중 스냅샷 교체, 동작 줄이기 설정을 검사했다. 공급 예고 1건의 공지 블록은 이 fixture에서 수신자당 112바이트였고, 이후 변경 없는 스냅샷에서 추가된 공지 바이트는 0이었다.

스크린샷은 가상 이름을 사용한 PC 브라우저의 모바일 크기 화면이다. 실물 스마트폰·태블릿 검사는 실행하지 않았다. 로컬 화면 기록 이후 저사양·저동작의 fade 비활성화, visual viewport 스크롤의 여백 갱신, 수동 시험 스냅샷 전달 커서와 팀 수 단언을 보완했다. 최종 제출 커밋의 회귀 결과는 PR의 CI에서 확인한다.

```powershell
node --test tests/unit/v34-broadcast.test.mjs
$env:PLAYWRIGHT_CHANNEL='msedge'
node tests/combat/v34-broadcast.mjs canvas
node tests/combat/v34-broadcast.mjs pixi
```
