## 1. Game Feel: 몸체 변형 기반 ‘적은 이펙트, 강한 감각’

### 1.1 기존 코드 확인 대상

- `apps/client/src/render/attack-pose.js`: `AttackPoses`, `poseEnvelope()`, `poseFamily()`와 현재 9종 pose family 및 서버 tick/생명/sequence 가드.
- `apps/client/src/render/renderer.js`: `actorBody()`, `image()`의 Pixi/Canvas 공통 회전·이동·압축.
- `apps/client/src/render/host-actors.js`, 학생 렌더 경로, `packages/engine/src/combat/heavy-feedback.js`의 **실제 wall contact** 이벤트 및 피격 event geometry.

기존 공격 신체압축은 되돌리지 않는다. 기본 원칙은 **같은 비트맵에 작은 affine transform**만 적용하는 것이다. 이모지가 팔·다리를 갖고 있지 않아도 질량과 방향을 읽을 수 있다.

### 1.2 공격 시 시각 동작

공격 동작은 **힘을 모으는 압축 → 공격 방향으로 짧게 늘어남 → 약간의 복원 탄성**. 현재 `heavy/slash/quick/recoil/burst/orbit/field/travel` 프로필 유지, 프로필별 단계가 보이도록 조정한다. 서버의 시전/입력/공격간격/투사체 생성 시점은 변경하지 않는다.

| 공격 프로필 | 첫 테스트용 시각 효과 | 금지 사항 |
|---|---|---|
| 강타(핵주먹·뿅망치·기관차 등) | 기존 heavy 강도를 약 15~25% 확대, 압축→전진방향 스트레치→복원을 **170~220ms** 이내. 서버상 명중 강도에 따라 표시의 강약만 구별 | 추가 실제 돌진·넉백·전역 freeze |
| 빠른 근접(검성·가위 등) | 매우 짧은 방향성 늘어남/복원 **70~110ms**, 연격에서는 매 프레임 새 효과 없이 재사용 | 잔상이 누적돼 캐릭터를 가림 |
| 일반 원거리 | 발사 방향으로 작은 반동·직전 압축 **80~140ms**, 연사는 진폭 상한 제한 | 발사 전에 입력을 지연시키기 |
| 강한 저격·포격 | 뒤쪽으로 짧은 반동과 몸체 복귀, 기존 발사 궤적 유지 | 신규 전용 발사음을 성공 필수 조건으로 삼지 않기 |
| 설치·버프 | 미세한 팽창·수축만 | 공격 자세로 ‘명중’을 암시하지 않기 |

스킬 준비가 **실제로 존재하는 경우**에만 준비 구간을 표시한다. 즉발 공격을 위해 클라이언트에 가상의 준비 지연을 만들지 않는다. 허공 타격에도 공격 동작은 허용하되 **명중 확정 피격 동작을 만들어선 안 된다**.

### 1.3 피격자의 별도 반응

공격과 다른 **‘외부 충격에 의해 눌리는’** envelope 구현. 피해가 들어온 방향을 기준으로 이모지를 약간 측면/진행방향에 압축하고, 뒤로 밀리는 듯한 방향성 변형 후 복원. 기존 hit pose를 재사용하되 attack pose의 동일 모션을 복사하지 않는다.

| 이벤트 | 권장 지속 | 표현 |
|---|---:|---|
| 작은 실제 HP 피격 | 65~95ms | 작고 빠른 찌그러짐 → 즉시 복원 |
| 중간 실제 HP 피격 | 85~120ms | 충격 방향으로 눌림·반대 방향 약한 흔들림 |
| 강한 실제 HP 피격 | 120~170ms | 깊은 압축, 일시적 회전(상한), 느리지 않은 복원 |
| 실드 흡수 | 75~110ms | 몸을 크게 찌그러뜨리지 않고 **보호막 테두리 반응**으로 구별 |
| 반사 | 90~140ms | 반사 주체의 짧은 튕김과 실제 탄환 방향 전환 |
| 장판 반복 피해 | 저강도·드문 갱신 | 0.5초마다 전신 hit pose 반복 금지 |

**서버의 위치·속도·충돌반경·HP·조작 잠금에는 영향 없음.** 피격 비주얼은 기절·공격 취소를 발생시키지 않는다. 현재 `attack-pose.js`는 actor별 single `active` entry를 사용하므로 **공격 pose를 피격 pose가 덮는 충돌**을 계측하고, 공격/피격/벽의 합성 우선순위(예: 강타/실피격 우선, 겹침 상한)로 해결한다. 우발적인 재시작/이중 이벤트를 막고, lifeSeq·castId·server tick과 연결한다. 스타일 합성값은 모든 조건에서 중립 상태로 복원돼야 한다.

### 1.4 넉백과 벽 충돌

**넉백 중:** 실제 권위 좌표로 밀리는 동안 몸체가 이동 방향으로 약간 길어지고, 반대 방향으로 미세하게 흔들리는 표현. 렌더-only 각도 ±0.10rad 이하·위치 오프셋 화면 2px 내외부터 검증. 저사양에서는 회전/길이만 유지.

**실제 벽 충돌:** 서버에서 확정한 접촉 법선(`heavy-feedback.js`의 `heavy-wall`)이 있을 때만 충돌 방향으로 이모지를 순간 찌그러뜨린 뒤 **1회의 작은 시각적 반동**. 150~200ms 이내, 바운스 위치는 화면 2~4 CSS px 정도의 비물리적인 *그림 오프셋*으로만 허용. 실제 게임 좌표에서 벽 반동/반발을 추가하거나 경계를 통과하게 하지 않는다. 나중에 물리적 반동을 넣으려면 별도 요청과 게임 물리 규칙 검증이 필요하다.

실제 벽 충돌이 없는데 벽 근처라는 이유로 연출을 발생시키지 않는다. 반복 접촉, 다중 튕김, 같은 cast의 여러 경계 처리에서는 연출을 bounded 1회로 제한. 전투 수치·벽 충돌 추가 피해는 **완전 불변**. 무게 있는 일부 공격에만 강조; 독/연사탄/일반 평타 전체에 강한 벽 반동을 넣지 않는다.

### 1.5 성능·가시성 계약

- Canvas/Pixi 동일 가시성. 이미 있는 타임라인/pose state, 스프라이트/텍스처 캐시 재사용. per-frame 신규 sprite, blur/filter/shader 생성 금지.
- 교사 전체 보기에서는 작은 몸체가 폭발적으로 커지거나 자주 회전하지 않도록 LOD. 학생 화면은 저사양에서도 중요한 공격·실피격이 읽히게.
- 평타 수십 발/초, 다수 학생 타격 중 피격 이벤트 중복은 bounded coalescing. 한 actor당 동시 시각 변형 상한과 종료 정리. reduced-motion은 변형을 최소화 혹은 비활성화.
- 단지 이름이 'squash'인 필드에 값을 과하게 늘려 위치 보간·클라이언트 자체 떨림을 재발시키면 FAIL. 캔버스 30인 / Pixi 30인 CPU·프레임·메모리 A/B 비교에서 악화가 있으면 축소/수정.

### 2.1 명시적으로 보류한 상향

- 볼링 스킬 피해 `21→26` **이번 패치 금지**. HP와 쿨타임 개선 후 실제 명중/교전 효율을 보고 후속 검토.
