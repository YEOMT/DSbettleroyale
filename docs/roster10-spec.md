## 3. 밸런스 초기값

### 3.1 보급/성장 상자 및 회복상자

**해석을 명확히 한다:** 이번 기본안에서 '보급상자'는 평소 전장에 생성되는 일반 XP/성장 상자를 가리킨다. `SupplyDrop`이라는 별도 공중 보급 이벤트의 출현 횟수·타이밍·보상은 유지한다. 코드와 보고서에서 두 개념을 혼용하지 않는다.

| 항목 | 초기 변경안 | 유지 |
|---|---|---|
| 초기 일반 XP 상자 | 기존 최종 목표 개수 ×1.10, 정수 반올림. 초기 상한 42→46 | 위치 검증, 상자 HP, 파괴 방식, 개당 XP |
| 후속 XP 상자 웨이브 | 기존 목표 개수의 평균 ×1.10. 웨이브 상한 8→9, XP 최대 상한 48→53 | 생성 간격 1200틱=20초, 수명, 레벨 MAX 시 추가 생성 중지 |
| 회복 상자 웨이브 | 기존 목표 개수의 평균 ×1.15. 회복 상자 동시 상한 6→7 | 기본 회복량 최대 HP의 20%, 수명, 생성 주기 |
| 부활 모드 상자 | 초기 XP 증가를 반영하고 기존 전체 상한 `count+3`을 새 count 기준 `count+4`로 조정 | 기본 리스폰 간격, 모드별 위치 제한, 재생성 큐 상한 |

- 소수 개 웨이브에서 매번 올림해 2→3처럼 50% 늘리지 않는다. 정수 목표와 0 이상 1 미만의 결정적 fractional carry로 평균 증가율을 맞춘다.
- XP와 heal의 carry는 별개이며 경기 시작 시 초기화한다. 유효 위치를 못 찾은 미생성분을 다음 웨이브에 대량으로 몰아 만들지 않는다.
- 새로운 실시간 타이머나 매 틱 재배치 루프를 만들지 않는다. 현재 웨이브/큐/공간 검사 흐름을 유지한다.
- 부활 모드에서 heal 재생성 큐가 cap을 넘어 회복상자가 늘어나거나, 반대로 XP가 전체 cap을 채워 heal 상향이 무효화되지 않는지 검증한다. 만료 항목을 포함한 예약 수까지 계산한다.
- 플레이어 시작점·벽·임시 벽·통로·점령 거점/기지 보호 영역에 상자를 겹쳐 생성하지 않는다.
- 생존자가 적고 안전구역이 좁아지는 후반의 기존 생성 억제 규칙은 유지한다.
- 개당 보상·치유량·파괴에 필요한 공격 횟수·사망 XP·수집 반경은 바꾸지 않는다.
- 개수 증가로 RNG를 더 소비하더라도 기존 전투/배정 RNG에 영향을 주지 않게 현재 별도 farm RNG를 유지한다.

### 3.2 B·C급 기본 HP

- B급과 C급의 **모드 배율·성장 적용 전 최종 기본 최대 HP ×1.06**.
- 타입/역할/캐릭터별 기존 override를 모두 반영한 뒤, 단 한 번 적용한다.
- S·A·F급 기존 캐릭터 HP는 변경하지 않는다.
- 초기 HP=변경된 최대 HP. 부활·리롤·재접속 때 1.06이 재누적되지 않는다.
- 기존 신규 B/C 캐릭터에도 같은 정책을 한 번 적용한다.
- 비율 회복·실드·모드 HP 배율은 기존 순서를 유지한다. 크기·속도·피해·방어력은 덩달아 바꾸지 않는다.
- 포탑·상자·분신 같은 비플레이어 객체에는 등급만 보고 이 버프를 적용하지 않는다.
- 최종 활성 B/C 전원의 전후 HP와 변화율, 다른 등급 불변 검사를 작성한다.

### 3.3 원거리 투사체 넉백

- 외부로 밀어내는 원거리 투사체의 기존 최종 기준 넉백에 **0.88배(-12%)**를 한 번 적용한다.
- 플레이어 원거리 평타, 원거리 스킬 탄, 포탑의 원거리 탄을 포함한다. 기존 0인 넉백은 0이다.
- 투사체 자체의 직접 타격 및 해당 투사체에서 파생된 폭발 밀침은 같은 출처로 분류하고, 직접/폭발 경로에서 이중 0.88배가 되지 않게 한다.
- 기존 최소값(`Math.max(...)`)이 감소를 무효화하지 않도록, 최종 힘이 산출되는 경로와 공통 피해/넉백 metadata를 조사한다.
- 근접 평타·근접 회전 공격·몸통 돌진·명시적 잡기/당기기·블랙홀 흡입·환경/벽 충돌 반응은 이번 공통 너프 대상이 아니다.
- 단순히 `entity.kind==='projectile'`만 보고 궤도형 근접까지 너프하지 않는다. 출처/공격 프로필과 실제 작용을 기준으로 한다.
- 피해량·탄속·사거리·공속·기절·넉백 저항은 그대로 유지한다.
- 반사/관통/다단 타격에서도 이미 조정한 힘을 재조정하지 않는다. 실제 displacement 검사와 설정값 검사를 함께 한다.

## 4. 호스트 이모지와 레벨 표시

### 4.1 목표

모든 참가자를 보여주기 위해 줌아웃하더라도 호스트가 캐릭터를 알아볼 수 있고, 레벨이 해당 이모지 바로 위의 정보라는 것을 즉시 알 수 있어야 한다. 새 연출이나 더 큰 텍스처를 추가하는 작업이 아니다.

### 4.2 표시 크기

- 서버 충돌 반경, 학생 화면의 실제 크기, 공격/스킬 범위는 변경하지 않는다.
- 호스트 전용 display radius를 계산해 몸체·팀 테두리·이름·HP·레벨이 이를 공유하도록 한다.
- 초기 기준: 1366×768의 전체 관전에서 일반 캐릭터 이모지 지름 최소 **28 CSS px**. 작은 화면이나 혼잡 구간은 **24 CSS px**까지 낮출 수 있으나 점으로 대체하지 않는다.
- 이미 더 크게 보이는 대형 이모지를 무조건 동일 크기로 축소하지 않는다. 충분히 확대된 구도에서는 기존 크기 차이를 살린다.
- CSS px와 물리 픽셀/DPR를 혼동하지 않는다. 예: `displayRadiusWorld=max(actualRadius, minDiameterCss/(2*zoom))`를 공통 함수로 사용하되 UI scale과 필요 최소 전환 보간을 둔다.
- 호스트에서만 조금 과장한 몸체 표현이라는 점을 유지한다. 그 표시 크기를 충돌·선택 조준·피해 계산에 역으로 전달하지 않는다.
- 13→12, 6→5, 3→2 모드 경계에서 크기와 라벨이 갑자기 도약하지 않게 한다. 카메라를 강제 확대해 다른 생존자를 화면 밖으로 밀지 않는다.

### 4.3 가까운 정보 묶음

- 레벨 텍스트의 **실제 보이는 하단**을 이모지 실제 표시 상단에서 4~6 CSS px 위에 둔다. 기존 큰 canvas의 투명 여백이 간격 계산에 포함되지 않게 한다.
- 이름은 레벨 바로 위에 배치하며 둘의 실제 텍스트 경계 간격은 2~4 CSS px로 시작한다. 또는 같은 가까운 묶음 안의 짧은 이름+레벨 배치를 사용한다.
- 이름·레벨·기절/실드 아이콘이 서로 덮지 않도록 상태 아이콘은 별도 옆칸 또는 한 줄을 사용한다. 상태에 따라 레벨을 멀리 날려 보내지 않는다.
- HP바는 같은 display radius 아래에 정렬한다.
- 혼잡하면 이름부터 축약/생략하거나 기존 겹침 처리를 사용한다. 이모지·레벨·팀 식별·현재 HP를 우선한다.
- `host-actors.js`, `host-canvas.js`와 공통 level pose의 좌표를 함께 수정한다. Pixi만 고치고 Canvas를 방치하지 않는다.

### 5.1 공통 기본 스탯과 평타

- 새 캐릭터의 기본 최대 HP·기본 이동·충돌 반경은 **기준 77종의 같은 등급+요청한 평타 역할**의 비탱커/비거대형 최종 유효 스탯 중앙값을 시작점으로 한다. 표본이 부족하면 공통 등급/역할 factory를 사용하고 근거를 기록한다.
- 기준 표본은 패치 전 데이터로 동결한다. 새 캐릭터끼리 서로를 참조하는 순환 중앙값이나 런타임 재계산을 하지 않는다. 선택한 최종 숫자를 명시적인 데이터로 고정한다.
- B/C의 +6%는 위 기본값에 정확히 한 번. 스킬을 DASH로 구현해도 원거리 평타 캐릭터가 근접 체력/평타를 자동 상속하지 않게 `statType`, `basic.close`를 명시한다.
- 근접은 기존 일반 부채꼴/전방 판정을 사용한다. 피그가 몸을 들이받는 외형이어도 접촉 자동 피해/돌진 평타를 새로 만들지 않는다.
- 원거리는 같은 등급의 기본 단발 사격을 사용한다. 신규 유도·관통·폭발·기절·자동스킬을 평타에 얹지 않는다.
- 시각 개성은 기존 glyph/색/짧은 베기/짧은 탄 꼬리에서 만든다. 조커 짧은 베기, 마운틴 팀 단발 탄, 왕 검격, 버섯 포자, 상어 깨물기, 판다 대나무 타격, 외계인 작은 에너지탄, 도깨비 방망이, 돼지 짧은 들이밀기, 쥐 작은 탄이 기본 방향이다.
- 기존 S가 무조건 큰 체형이어야 한다는 식의 보정을 추가하지 않는다. 강한 유틸리티와 강한 기본 스탯을 동시에 과도하게 주지 않는다. 기존 캐릭터 하나의 유효 스탯을 복사한 뒤 생성자의 역할 배율까지 다시 곱하지 않는다. stats override의 적용 위치를 확인해 산출된 최종 기본값이 그대로 나오는지 검사한다.
- 새 효과는 기존 공격/피격 연출과 가시성을 연결한다. 신규 대형 파티클·blur·실시간 그림자·텍스트 효과·외부 자산 의존 없음.

## 6. 캐릭터별 구현 계약

### N01 🤡 조커 — S / 근접

핵심은 짧은 기습·탈출과 속임수이지, 별도의 AI 군대를 추가하는 것이 아니다.

1. 조준한 방향/거리로 최대 240 순간이동한다. 기존 목표점/안전 착지 기능을 재사용한다.
2. 새 벽 관통 능력은 부여하지 않는다. 첫 차단물 전에 안전하게 착지한다. 보호 구역/경기장 경계/임시 벽도 반영한다.
3. 유효 시전에서 본체는 1.2초 은신한다. 평타/새 스킬을 실제 발동하거나 피해를 받으면 일찍 해제한다. 취소된 버튼 입력은 은신을 해제하지 않는다.
4. 기존 ghost의 매복 추가 피해·벽 통과·무적·적 관통 보너스를 자동 상속하지 않는다.
5. 이동 직전 위치에 동일 이모지의 분신 1개를 만든다. 최대 5초, 분신 HP=시전 순간 본체 최대 HP의 25%. 피해로 먼저 사라질 수 있다.
6. 이번 기본안의 분신은 **무피해 미끼**다. 본체의 유효 이동 방향을 단순히 따라 이동하되 같은 벽/경계를 지키며, 정교한 적 탐색·길찾기·스킬·연쇄 소환·경험치 획득은 하지 않는다.
7. 분신은 적 탄/근접 공격의 유효 표적이 될 수 있다. 피해 기록은 분신용 HP로만 처리하고 킬·XP·흡혈·처치 발동·점령 점수·생존자 수·시상 통계에는 영향을 주지 않는다.
8. 진짜 참가자/방 멤버/접속 세션을 추가하지 않는다. 고유한 presentation/decoy ID와 owner/life/cast ID를 가진 경량 엔티티로 처리한다.
9. 상대에게는 본체와 비슷한 이름·외형, 본인/아군/교사에게는 가벼운 구분 표시를 줄 수 있다. 분신 표시로 은신한 본체의 좌표나 연결선을 노출하지 않는다.
10. `clone`이라는 이유로 호스트 그리기에서 skip되거나, 분신과 본체가 같은 ID를 써 서로 덮이는 문제를 검사한다.
11. 기존 은신·연막 정책은 지킨다. 본체와 분신을 강제로 모두 공개하는 우회 수정 금지.
12. 재시전은 기존 분신을 교체. 본체 사망/생명 변경/퇴장/경기 종료에서 정리하고, 일시 네트워크 끊김은 서버 수명대로 진행한다.

### N02 🤠 마운틴 팀 — S / 원거리

핵심은 **맞은 대상을 당기는 훅이 아니라 시전자 자신이 앵커로 이동하는 밧줄**이다.

1. 방향 조준으로 최대 800까지 한 개의 밧줄 머리를 발사한다. 최대 범위는 고정이며 조준선은 첫 충돌 예상 지점을 표시한다.
2. 연속 충돌 검사로 진행 경로의 첫 유효 표면/대상을 잡는다. 벽, 파괴 가능한 상자, 실제 몸체가 있는 포탑/설치물, 다른 살아 있는 플레이어(아군 포함), 새 임시 벽을 포함한다.
3. '다른 오브젝트'는 충돌/앵커로 등록된 실체가 있는 객체다. XP·회복 드롭, 파티클, 투사체, 장판, 안개, HUD, 장식에는 걸리지 않는다. 모든 객체를 무조건 앵커로 만들지 않는다.
4. 가장 가까운 접촉을 한 번만 확정한다. 벽 너머 플레이어를 잡지 않으며 후보 동률은 결정적으로 처리한다.
5. 접촉 순간의 안전 도착점으로 시전자만 빠르게 이동한다. 이동 중인 상대를 계속 쫓아가는 호밍 이동은 하지 않는다.
6. 상대/상자의 중심이 아닌 자신의 반경을 고려한 접촉 직전 위치에 선다. 이동 중 새 장애물이 생기거나 앵커가 사라지면 마지막 안전 위치에서 종료한다.
7. 스킬은 **피해·넉백·당기기·기절·상자 파괴·적중형 증강/흡혈 발동 모두 0**이다. `R.hit(0)` 호출의 부작용까지 피한다.
8. 밧줄 비행 중에는 보통 이동 허용, 당겨지는 동안에는 기존 강제이동 입력 잠금을 사용한다. 모든 정상/비정상 종료에서 잠금을 해제한다.
9. 범위 끝까지 못 맞히면 이동하지 않고 종료한다. 수동 취소/빗나감의 쿨타임은 기존 유효 시전 규칙에 따라 소모한다.
10. 기절·사망·다른 강제이동·생명 변경은 취소한다. 출발점 고정의 영구 선, 도착 후 남는 밧줄, 재접속 후 이중 당김을 금지한다.
11. 밧줄 줄기는 현재 손잡이 위치와 머리/확정 앵커를 연결한다. 장식용 연결선이지 별도 광선 피해 판정이 아니다.
12. 이동 거리와 속도는 클라이언트가 확정하지 않는다. 기존 서버 이동 상태를 전송하고 로컬 예측은 그 권위 상태에 맞춘다.

### N03 👑 킹 오브 데마시아 — S / 근접

핵심은 진입해서 자신도 함께 갇히는 5초의 작은 결투장이다. 원을 그리기만 하고 실제로는 통과되는 장식 스킬로 만들지 않는다.

1. 방향/거리 조준으로 최대 420 돌진한다. 기존 swept dash를 재사용하고, 첫 적 접촉 또는 벽/최대거리에서 멈춘다.
2. 첫 유효 적에게 피해 계수 60을 한 번 적용한다. 추가 기절·강제 밀침·벽 충돌 보너스는 주지 않는다. 실제 몸 충돌로 겹치지 않게 한다.
3. 적을 맞히면 안전한 종료 위치의 자신과 그 상대를 포함하는 중심으로 원형 임시 벽을 만든다. 기본 중심은 두 몸체 중심의 중간, 기본 반경 260이다.
4. 상대가 없으면 유효 돌진 종료 위치의 자신 중심으로 생성한다. 범위 안의 다른 플레이어도 동일하게 갇힐 수 있다. 1:1 전용으로 순간이동시키거나 적을 링 안으로 강제 이동시키지 않는다.
5. 큰 몸체를 완전히 담기 위해 필요한 경우 반경을 `max(260, 각 몸체 중심거리+실제반경+24)`로 늘리되 초기 상한 360. 생성 가능한 공간이 없으면 돌진/이미 확정된 피해는 유지하고 벽 생성만 실패한다. 무리한 강제 위치 보정 금지.
6. 벽은 유효 생성부터 정확히 300틱 후 사라진다. 소유자당 1개이며 재시전은 기존 것을 먼저 정리한다. 시전자 사망/생명 변경/경기 종료 시 일찍 정리한다.

## 8. 데이터·코드 일관성

### 8.1 단일 유효 콘텐츠 정의

- raw EMOJI_DB → display/name overrides → rework definitions → 최종 stats → manifest/display/hash의 실제 흐름을 먼저 추적한다.

- 기존 parity 테스트는 승인된 HP/넉백/상자/지니/호스트 변경만 allowlist로 예외 처리하고 나머지 기존 77종 불변을 계속 검사한다. 테스트 전체를 제거하거나 snapshot을 무작정 재승인하지 않는다.

### 8.2 엔티티의 공통 수명

모든 신규 상태/엔티티는 `matchId + ownerId + lifeSeq + cast/actionSeq + entityId`를 통해 유일하게 식별한다. ID를 렌더 프레임마다 새로 만들지 않는다.

반드시 확인할 종료 사유: 자연 만료, 피격 파괴, 같은 소유자 재시전/교체, 소유자 사망/생명 변경, 기절/강제이동 취소(능력별 정책), 탈퇴, 경기 종료, 재경기, 방 폐기.

- 일시적인 네트워크 끊김은 시뮬레이션을 초기화하거나 스킬을 재시전하지 않는다.
- 순간이동은 기존 warp sequence를 올리고 보간을 리셋한다. 대시는 정상 연속 이동이며 매 틱 warp처럼 처리하지 않는다.
- FULL_STATE는 남은 시간과 현재 위치를 복원한다. 과거 시전 이펙트/사운드를 처음부터 재생하지 않는다.
- 새 엔티티의 생성/제거/표현은 PR #8의 배치 전송·큐 상한·중복 제거 흐름을 사용한다.
- 화면 밖 decorative 객체는 비용을 줄일 수 있지만 유효 투사체·트랩·임시 벽·장판의 위험 정보는 거리/시야 규칙에 맞게 항상 전달한다. 새로 시야에 들어온 지속 엔티티도 보인다.

## 9. 성능 설계 — 신규 10종을 넣어도 전투가 버거워지지 않게

1. 모든 수명은 기존 60Hz tick 기반, 별도 캐릭터별 setInterval/setTimeout 없음.
2. 스킬별 시간 제한과 owner cap을 설정한다. 클론 1, 밧줄 1, 링 1, 버섯 3/독 2. 방 전체에서 조용히 타인 스킬을 지우는 임의 global cap은 넣지 않는다.
3. clone은 full Player/Peer/AI를 추가하지 않는다. 기존 decoy/target 인터페이스를 최소 확장하고 이동·피격만 계산한다.
4. 밧줄은 세그먼트+첫 충돌 계산이다. 로프 물리/관절/다수 파티클 시뮬레이션은 하지 않는다.
5. 원형 벽은 생성 때만 geometry를 만든다. 고정 조각/공간 인덱스/변경 revision으로 처리하고 20Hz snapshot마다 전체 벽을 중복 재생성하지 않는다.
6. 반복 원/실드/버섯은 기존 캐시 glyph/도형/스프라이트를 사용한다. 매 프레임 canvas·Texture·TextStyle 생성 금지.
7. 신규 UI는 실제 상태가 바뀔 때 갱신한다. HP/레벨/이름 간격 개선을 이유로 이름 텍스처를 매 프레임 다시 만들지 않는다.
8. 이벤트 batching과 사망자 표시 제거 최적화를 유지한다. clone·wall을 넣으려고 모든 사망자 몸체 전송을 다시 켜지 않는다.
9. 공격 수·투사체 본체·판정·입력·필수 경고를 줄여 부하검사를 통과시키지 않는다. 평균 FPS만으로 후반 끊김 해결을 선언하지 않는다.
10. 성능 비교에는 같은 기기/서버 제한/네트워크/시드/품질/해상도/클라이언트 수와 비슷한 전투 강도를 사용한다. 신규 로스터 부하와 구버전 동일 로스터 비교를 구분한다.
11. 현재 서버의 실제 제한을 조회한다. 저장소 Compose의 2CPU/1GB 값이 실제 Lightsail 사양과 같다고 단정하지 않는다. CPU credits만으로 코어 병목/스케줄링 지연을 배제하지 않는다.

## 11. 검증 시간을 불필요하게 늘리지 않는 방법

- 기존 Quick/Targeted를 사용한다. 새 10종·변경된 공통 경로·상호작용 검사에 집중한다.
- 87종 전체 데이터/handler/aim/capability 검사는 빠르게 공통 실행하되, 모든 캐릭터×모든화질×모든화면의 긴 브라우저 전수 감사는 기본으로 돌리지 않는다.
- 브라우저 fixture 한 개를 재사용해 신규 10종을 순차 시험한다. Canvas/Pixi 양쪽 필수 표시, 모바일 멀티터치, 대표 호스트 구도는 포함한다.
- 공통 CI job의 기존 10분 상한은 유지한다. 600초 시험을 그 상한 안에 억지로 넣지 않는다. 장시간 성능검사는 별도 명시적 job/실행으로 준비·정리를 포함한 15분 수준 상한을 둔다.
- 장시간 검사는 최종 관련 런타임 변경 후 한 번 수행하고 원시 결과/소스 SHA/fixture 해시를 보존한다. 보고서·비실행 문구 변경만으로 반복하지 않는다. 실행 경로가 바뀌면 관련 시나리오만 재실행한다.
- 로컬 상이한 캐릭터 통과를 모든 87종 현장 안정성 통과로 포장하지 않는다.
- timeout/미실행을 PASS로 처리하지 않는다. 재시도를 통해 우연히 한 번 통과한 것만 골라 제출하지 않는다.
- 최소 두 장시간 실행이 필요한 이유는 기존 후반렉 회귀와 신규 지속엔티티의 누적을 확인하기 위함이다. 그 외 무관한 감사/새 리팩터링을 추가하지 않는다.
