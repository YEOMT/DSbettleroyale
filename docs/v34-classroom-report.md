## 병합 후 CI 재현

main 실행 [42866022240](https://github.com/YEOMT/DSbettleroyale/actions/runs/42866022240)에서 호스트의 snapshot 44에 이어 학생의 45도 도착했다. 캡처된 학생 HUD와 권위 패킷은 모두 BLUE 2 / RED 1, BLUE 득점이었다. 시험이 읽은 수신 경과 시간은 1,638.8ms였다. 동결된 실제 Pixi fixture에서 수신과 자동화 관측 사이에 1,700ms를 추가해 같은 단언 실패를 재현했다(1,718.5ms). 연결 종료 시 출력된 Vite 프록시 오류만으로 수신 실패라고 판정할 근거는 없었다.

현재 검사는 정상 앱의 snapshot 처리기가 끝난 동일 dispatch에서 해당 sequence의 HUD, 인원, 수신 경과를 읽는다. HUD 위치는 ResizeObserver 적용 후 두 렌더 프레임을 거쳐 측정한다. 첫 수정에서 레이아웃까지 dispatch 안에서 읽으면 기존 비겹침 단언이 실패하는 것도 확인했다. 최종 지연 주입 Pixi 시험은 원래 단언과 sequence 일치 단언을 통과했다. 실행 명령은 `CAPTURE_OBSERVER_DELAY_MS=1700 node tests/combat/capture-x.mjs pixi`다.

기존 [후보 실행 42867891924](https://github.com/YEOMT/DSbettleroyale/actions/runs/42867891924)는 candidate와 staging Job이 skipped였고 artifact는 0개였다.

## 20인 계측 방법

세 버전에 같은 `classroom-authority.mjs`, `classroom-rematch.mjs`, `classroom-meter.mjs` 시험 도구를 사용했다. 이전 버전은 각각의 Git archive에서 실행했다. 같은 Windows PC와 Node 24.22.1, 별도 권위 서버 프로세스, 고정 맵 0과 매치 seed, 003/034/070/141 조합이다. 교사 브라우저 1개, 학생 브라우저 2개, 가상 WS 학생 18개로 총 학생 20명을 유지한다. 솔로/점령 각각 동일 방 3라운드에서 이동·평타·스킬, 재접속, Results/Rematch와 자원 정리를 단언한다. 서버와 브라우저가 PC 자원을 공유한다.

각 checkout에서 `CLASSROOM_UPGRADE=1`, `CLASSROOM_METER=1`, `CLASSROOM_MODE=solo` 또는 `team-capture`를 설정해 `node tests/combat/classroom-rematch.mjs <label>`을 실행한다. 로컬 Edge는 `PLAYWRIGHT_CHANNEL=msedge`를 사용했다. CPU는 프로세스 user+system 누적시간, RSS는 250ms 간격 표본과 프로세스 최대값, 관리 힙 할당량은 V8 GC 전후 회수량과 시작·끝 힙 차이를 합한 추정치다. 실제 전송 bytes와 준비된 snapshot 크기는 별도 지표다.

점령 X 지형의 네 변은 큰 회전 사각형이다. 20인 기준선에서 작은 셀 인덱스의 생성 bucket 합계가 714→7,858로 늘었다. 동일 고정 지도에서 기존 인덱스는 786개 bucket을 사용했다. 큰 terrain 벽의 범위를 각각 한 번 보관할 때 작은 벽·상자의 bucket은 47개이고 큰 벽 기록은 4개다. 후보를 기존 벽 순서로 정렬하고 같은 정밀 충돌 함수를 사용한다. 64방향 × 3개 반경에서 전체 벽 검사와 가장 먼저 닿는 대상·시각을 대조했고, X 경계·도약·특수탄까지 집중 13검사를 통과했다. 이 비용으로 과거 RSS 차이 전체를 설명할 수는 없다.

실물 교실 20대, 장시간 605초, 전 캐릭터·화질 전수 리그 및 공개 배포는 NOT_RUN이다.
