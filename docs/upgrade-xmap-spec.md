## 0. 개발 원칙과 범위

- 최근 **실학생 약 15~20명** 플레이에서 대부분 원활했고 체감 렉이 감소했다는 관찰을 최우선으로 존중한다. 극후반 교사 관전의 약간의 끊김을 이유로 렌더러·게임 엔진을 대규모 재작성하지 않는다.
- **기존 AWS 1GB 서버, GitHub Pages 공식 주소, WebSocket, 서버 권위 60Hz 엔진/기존 스냅샷·입력 흐름, 배포·롤백 절차, 6레벨·증강·87종 기존 스킬 중 유지 대상의 수치와 게임 규칙**을 보존한다.
- 이번 패치의 범위는 ① 일반 생존전의 **단방향 비상 포탈 A→B 1쌍 (실물 2개)**과 **가속 발판 4개**, ② 팀 점령전 **넓은 X자 맵·2거점·HP 상향·상황 UI/공지**, ③ **볼링 챔피언/다트 챔피언** 2종 리워크, ④ **4종 완전 삭제**, ⑤ **캐릭터 전수 문구 정합성 수정**으로 한정한다.
- 이전 논의의 외계인·비누·구급차·도깨비 리워크와 신규 이모지는 **이번에는 구현하지 않는다**. 다른 캐릭터의 밸런스·조준 보정·퀴즈·카운트다운·재접속·동일 방 재경기도 변경하지 않는다.
- **숫자 선택 원칙:** 사용자가 지정한 20초/15초/단방향/중앙 1.5배 치명타/공속 5초는 확정. 아래에 `초기 제안`이라고 표시한 속도·반경·넉백·HP는 첫 빌드 값이며 정합성 시험에서만 보수적으로 조정한다. 변경값은 결과 보고서에 적는다.
- 한 프레임마다 대상 탐색·새 애니메이션 오브젝트 생성·추가 서버 타이머를 남발하지 않는다. 기존 월드 수명, 충돌 브로드페이즈, 정적 지형 캐시, 이미 전송 중인 상태에 최소 필드만 추가한다.

## 1. 일반 생존전: 단방향 비상 포탈 (확정)

### 1.1. 배치

- 일반 **솔로 배틀로얄 맵**에 포탈 **총 2개**를 설치한다: **진입구 A 1개 → 출구 B 1개**. 사용자의 ‘맵에 두 개 정도’를 *실제 맵에 놓이는 포탈 오브젝트 2개(단방향 링크 1개)*로 해석한다. 서버의 재충전 상태는 이 한 링크가 공유한다.
- **B에서는 절대로 A로 역이동할 수 없다.** 출구 B는 접촉만으로 재발동하지 않는다. A와 B 외에 다른 목적지·진입구는 만들지 않는다.
- 지도 가장자리 또는 막다른 벽 앞에 두지 말 것. 맵 중심에서 너무 멀지 않은 중간 거리(참고: 월드 반경의 대략 35~65% 지대)를 우선 검토하고, **탈출 후 두 방향 이상의 퇴로·엄폐물**이 있는 안전한 곳으로 출구를 배치한다.
- 각 맵 프리셋(현재 존재하는 맵 선택/랜덤 포함)에 대해 위치를 검증한다. 벽·상자·장판 위험 구역·리젠 영역 및 A와 B 자체가 서로 겹치지 않아야 한다. 정적 배치를 우선하고, 재시도 무한 루프나 매 프레임 유효 지점 탐색을 추가하지 않는다.
- 입구 A는 밝은 화살표와 `A → B`, 출구 B는 `출구 / 역이동 불가`로 구분한다. 미니맵에도 단순 기호로 표시한다. 사용 가능/재충전 상태는 색·간단한 잔여 시간 등으로 구별한다.

### 1.2. 발동 규칙

- 게임 시작 시 **사용 가능**. 유효한 학생 캐릭터 **한 명**이 A에 들어오면 서버가 원자적으로 성공 여부를 확정하고 안전한 B로 즉시 이동시킨다.
- 성공한 순간 **A/B 모두 20초간 닫힌 상태**로 표시한다. B는 원래 출구 전용이며, 실제 재사용 제한 대상은 A 진입구다.
- 20초가 경과하면 A/B가 다시 사용 가능으로 표시되며, **누군가 사용할 때까지 열린 채 유지**된다. 매 20초마다 1초만 열리는 시간제 창은 구현하지 않는다.
- 포탈 입구를 여러 명이 동시에 밟아도 **한 명만 전송**한다. 순서는 서버의 기존 결정적 입력/시뮬레이션 순서로 처리하고, 성공 이후 나머지는 이동시키지 않는다. 이용자 개인 추가 쿨다운은 별도로 만들지 않는다.
- 정상 상태(살아 있음·해당 모드·맵 내)에 한해서만 발동. 돌진·끌려가는 중·순간이동·부활 보호 처리와 충돌하지 않도록 기존 이동/상태 잠금을 존중한다. 가짜 분신·소환수·포탑은 발동 대상이 아니다.
- 도착 때 속도/위치 보간 기록을 정상화해 캐릭터가 순간적으로 다시 원위치로 미끄러지거나 화면 밖으로 튕기지 않게 한다. **HP·방어막·기존 버프·쿨다운은 그대로 유지**하며, 포탈 사용 자체에 공격력·회복·무적을 새로 부여하지 않는다.
- 자기장이 좁아져 **B 도착지가 현재 안전구역 밖**이거나 출구가 폐쇄/차단돼 안전한 배치가 불가능하면 **해당 포탈을 사용 불가 상태로 표시**하고 안전한 새 목적지를 임의의 적 근처에 만들지 않는다. 자기장/맵 전환 후 재사용 정책은 서버 판정에 일치시킨다.

### 1.3. 성능/수명

- 포탈 A/B 위치·단방향 연결 관계는 **정적 맵 데이터**로, 공유 사용 가능 시각 1개만 서버에 저장한다. **개별 setInterval 불필요**. 기존 전투 틱 또는 저빈도 환경 기믹 처리에서 접촉을 검사한다.
- 네트워크는 사용 순간·충전 상태 변경 등 **상태 전환 기반**으로 갱신하며, 모든 학생에게 매 틱 카운트다운 패킷을 전송하지 않는다. 클라이언트는 서버 `nextReadyAt` 기반으로 잔여 시간을 계산한다.
- 캔버스·Pixi·미니맵은 기존 그리기 및 정적 자원을 재사용한다. 영구 파티클 방출·빛 번짐·새 오디오 채널은 추가하지 않는다.
- 월드 종료/같은 방 재경기/접속 복구/새 맵에서 포탈 상태와 위치가 **해당 경기 스코프**로 새로 생성·정리되도록 한다.

## 2. 일반 생존전: 가속 발판 (이전 합의 유지)

- 포탈과 별개로 일반 솔로 BR 맵에 **가속 발판 4개** 배치. 위치는 엄폐물과 탈출 경로 인근의 중간 지대. 전부 중앙 한곳에 집중시키거나 외곽에서만 획득하게 하지 않는다.
- **발판별** 처음 사용 가능, 한 명이 밟으면 그 학생에게 **3초간 이동속도 +30%** (*초기 제안*) 부여 후 **15초간 비활성화**. 다른 발판의 상태에 영향 없음.
- 한 명의 학생이 발판 안에 계속 서 있을 때 재충전 완료 즉시 반복 적용되지 않도록, **외부에서 진입한 접촉** 또는 재진입을 필요로 한다.
- 같은 발판 버프는 **중첩하지 않는다**. 다른 고유 스킬·증강과의 조합은 기존 이동속도 버프 정책을 유지하되, 예기치 못한 무한 중첩이나 재경기 잔존은 방지한다. 공격 속도·HP·회복은 변경하지 않는다.
- 활성/비활성은 읽기 쉬운 정적 문양·테두리로 표시하고, 중요한 상태 변환 시만 갱신. 버프 시간 종료는 기존 상태 프레임에서 처리한다. 환경 장판을 일반 피해 장판 엔진으로 억지로 구현해 불필요한 충돌/틱 계산을 늘리지 않는다.
- **이번에는 솔로 BR 우선 적용. 팀 점령전의 포탈·발판 도입은 제외**한다. 다른 팀 모드로 자동 확산하지 않는다.

## 3. 팀 점령전: ‘넓은 X자’ 아레나 (확정)

### 3.1. 맵 동선과 팀 배치

- 점령전 `team-capture` **전용 맵**. 현재 가로 직사각형 중앙 3거점을 **네 갈래의 넓은 X형 진입로 + 넓은 교차 중앙 광장 + 2개 거점**으로 교체한다.
- `X`는 **실제로 이동 가능한 지형/통로 구조**여야 한다. 바닥에 X무늬만 그려놓고 평평한 직사각형 전장을 유지하면 불합격이다. 다만 비싼 새 다각형 물리 엔진 대신 **기존 정적 벽·경계 충돌, 지형 캐시**를 우선 재사용한다.
- **중앙은 좁은 한 점이 아니라 넓은 광장**으로 구성하며, A와 B 중 어느 쪽이든 여러 방향에서 접근·이탈할 수 있어야 한다. 지나치게 긴 단일 사격선, 통과 불가능한 병목, 벽 사이 끼임, 일방적인 봉쇄는 피한다.
- 거점 밖 또는 옆에 **소수의 정적 엄폐물**과 **거점에서 다른 팔로 빠져나가는 비상/우회 통로**를 배치한다. 이 ‘비상 통로’는 이동 가능한 **일반 지형 통로**이지 솔로 BR의 순간이동 포탈과 다르다. 좁은 통로 하나만 남겨 가둬두지 않는다.
- **네 모서리/팔 끝의 팀 시작 위치:** 왼쪽 위(TL), 오른쪽 위(TR), 왼쪽 아래(BL), 오른쪽 아래(BR). 아래 배치는 *맵 방향 기준*이다.
  - **2팀:** TL 대 BR (서로 마주 보는 대각선), 다른 두 곳은 비움.
  - **3팀:** TL·TR·BL 사용, **오른쪽 아래 BR은 비움** (*사용자 확정*).
  - **4팀:** TL·TR·BL·BR 전부 사용.
- 3팀은 빈 팔을 포함한 비대칭이 생길 수 있으므로, 팀별 거점 최단 거리·첫 합류시간·유효 엄폐량을 측정해 기존 지정 슬롯을 유지한 채 출발 위치와 통로 길이를 조정한다. **3팀을 금지하거나 네 번째 팀/AI를 자동 생성하지 않는다.**
- 실제 지형 밖에서는 스폰·이동·돌진·벽 통과 기술·순간이동 도착·넉백·상자 생성이 모두 정합성을 유지해야 한다. 기존 좌표 경계가 단순 `rect`인지 확인해, 경로/안전 좌표가 X자 지형의 막힌 부분을 통과하지 않도록 검증한다.

### 3.2. 거점과 체력

- **A·B 두 거점만** 존재. 이전 중앙 `B` 잠금과 `A/B/C` 3거점 및 중앙 1.5배 보너스는 새 점령전에서 제거한다.
- **두 거점 모두 경기 시작 즉시 활성**, 동등한 점수 획득 배율 `1.0`. 위치는 중앙 광장 안의 서로 겹치지 않는 자리.
- **각 거점 반경 초기 제안 400 월드 단위**. 현재 외곽 250 / 중앙 320보다 크게 한다. 같은 캐릭터가 동시에 두 점령 원 안에 서지 못하도록 간격 확보. 실제 중앙 공간과 성능·교전 시야를 보고 초기 수치는 조금 조정 가능.
- 점령전 HP 배율 **기존 0.70 → 0.85** (*앞서 합의한 첫 적용 값*). **일반 BR/팀 킬의 HP 배율은 그대로**. 피해량·스킬 배율·레벨업·회복/실드 배율을 추가로 바꾸지 않는다.
- 기존 기본 득점 공식(유일한 최다 팀의 인원 우세로 득점, 최다 동수면 득점 정지), 시간 제한, 페이즈 마지막 피버, 100점 승리/정산, 킬·점령 MVP는 가능하면 보존한다. **거점 수 변경**에 따른 인덱스·마스크·배율·결과·통계·네트워크/렌더러 배열 길이 가정을 전부 점검한다.
- 기존 `openingMask:5`, `openingSeconds:120`, `pointMultipliers:[1,1.5,1]`에 대한 의존을 제거하거나 새 2거점 규칙으로 안전하게 치환한다. *두 거점을 켠 뒤 120초 후 세 번째 거점을 여는 이전 페이즈가 남아선 안 된다.* `mapRevision`/프로토콜 콘텐츠 버전은 변경에 맞춰 갱신한다.

### 3.3. 시각화·전체 공지

- 항상 보이는 HUD에 두 거점을 각각 작은 카드로 표시: **`A | BLUE 3 · RED 1 | BLUE 우세·득점 중`**, **`B | BLUE 2 · RED 2 | 경합·득점 정지`** (3·4팀이면 해당 팀도 표시). 팀 색깔에 의존하지 않고 텍스트·숫자를 함께 제공.
- 실제 판정 규칙: **서로 다른 두 팀이 존재한다는 이유만으로 득점 정지가 아니다**. 한 팀이 유일하게 가장 많으면 우세 득점, 최다 인원이 동수이면 경합·정지. 점령자 수는 점령 가능 실제 학생만 포함, 소환수·분신·스폰 보호 중 참가자는 기존 정책대로 제외.
- 거점 바닥 원은 현재보다 명확한 **넓은 테두리·적당한 투명도·팀 색상·A/B 표시**. 지나치게 불투명한 덮개·많은 이펙트·상시 깜빡임을 금지. 지도·미니맵·학생·교사 화면 모두 표시 일치.
- 전체 공지는 **중요한 상황 전환에만** 노출: (1) 한 팀 우세가 변경되어 **2초간 유지**, (2) 한 팀이 **A와 B 동시 우세 득점**, (3) **승리 임박/중요 역전/피버 시작**. 개별 선수의 진입/이탈·1프레임 경합 변동에는 공지하지 않는다.

- 구현은 기존 authoritative capture packet의 점수·거점별 인원·우세 팀·경합 상태에서 **상태 변화가 있을 때만** 파생한다. 플레이어마다 별도의 비싼 거점 스캔, 신규 고주파 네트워크 메시지, 중앙 텍스트 오브젝트 반복 생성을 추가하지 않는다.

## 5. 캐릭터 리워크 2: 🎯 다트 챔피언 `emoji-070` (B급)

### 5.1. 일반 공격: 중앙 명중 시 1.5배 치명타 (확정)

- 기존 관통 다트 일반 공격을 기본으로 유지. **상대 플레이어의 몸 중심부에 맞히면, 해당 일반 공격의 실제 피해 계산 입력에 ×1.5 배율**을 적용한다.
- ‘중앙 명중’은 **랜덤 확률이 아니라 기하학적 판정**이다. 기준 제안: 발사체의 실제 서버 궤적과 상대 캐릭터 중심의 **최소 거리 ≤ 상대 충돌 반경의 35%**. 충돌 순간의 첫 표면 접촉점은 원래 캐릭터의 테두리에 있으므로 이를 그대로 중심 거리로 계산하는 잘못된 공식을 사용하지 않는다.
- 피격 순간의 서버 상대 위치와 **swept collision / 고속 투사체의 실제 이동 선분**을 기준으로 한다. 프레임 건너뛰기, 이동 중 대상, 큰 몸집, 관통 다트 연속 적중 시에도 동일 규칙. 이미 유효 타격한 대상만 판정하며 벽 뒤·아군·은신·스폰 보호·무효 충돌에 치명타를 발동하지 않는다.
- **일반 공격에만 적용**, 스킬 피해·환경·상자·분신·소환수·반사 대미지에는 배율 없음. 방어막·방어율·킬 통계·피해 피드백은 기존 `takeDamage` 한 번의 결과를 사용, 이중 피해를 발생시키지 않는다.
- 치명타 발생 시 작은 타격 이펙트로 구별 가능하게만 하고 **화면을 가리는 문구·추가 타격수·독립 투사체 없음**. 기본 공격력·속도·사거리·관통 수는 별도 변경하지 않는다.

### 5.2. 스킬: 5초 공격속도 버프 (확정)

- 기존 다트 3발 관통 투사 스킬을 제거하고, 사용 시 **자기 일반 공격속도를 5초간 +30%** (*초기 제안: 공격 빈도 1.30배, 즉 간격/1.30*) 올리는 **자가 버프**로 변경한다.
- 스킬 활성 중에도 이동·일반 공격 가능. 별도 공격탄·추적탄·자동타격·기절·지속 피해 없음.
- 기존 스킬 대기시간 **약 16.5초 유지**를 초기 원칙으로 한다. 버프는 반복 시전·증강 등으로 무한 중첩되지 않고 사망/새 생명·매치 종료/재경기에 누수되지 않는다. 기존 일반 공격속도/쿨타임 강화와의 연산 순서를 확인한다.
- 평타 **중앙 적중 치명타는 버프 중에도 같은 기준**. 예상 명중률·DPS 상승이 과도하지 않은지 고정 샘플로 비교한다.
- `emoji-070`의 native 스킬 프로필, `BR_V32_NATIVE_SKILLS`, `display.cards`·`manifest`, 공격 가이드 및 팀 스코어 등의 구 스킬 정보를 함께 수정한다.

## 7. 83종 ‘옛 콘셉트 문구’ 전수 정리 (확정)

- 이미 드러난 예시: **농구왕의 ‘원반’ 문구**, **통조림 투척의 ‘화분’ 문구**, **롤러스케이트의 ‘폭탄을 남김’ 문구** 등 실제 동작과 어긋나는 내용을 우선 수정. 과거 세 갈래·여섯 발 등 리워크 이전 표현도 전수 확인. 빈 `고유 스킬`이나 중복 수식은 정확한 이름으로 교체.
- 원래 학생에게 익숙한 캐릭터 **이름/이모지/개성은 유지**. 이번 텍스트 정리 과정에서 다른 83종 스킬/수치가 바뀌면 안 된다. 설명에는 사용자가 실제로 판단할 수 있는 문구를 쓰고, 모호한 ‘강력한 공격’ 같은 표현을 피한다.
