# v35.1 변경 및 복구

전투 규칙·콘텐츠와 서버 60Hz, 목표 스냅샷 20Hz는 v35를 기준으로 한다. 변경의 효과는 독립된 서버, 지터 재생, 실제 브라우저와 소켓 연결에서 나눠 측정한다. [측정 조건과 결과](v35-1-baseline.md)

관전·학생 화면, 입력 복구, 송신 경로의 검증 결과와 원자료는 리뷰 브랜치에서 관리한다. 운영 자격증명이나 실제 학생 로그는 사용하지 않는다.

## 학생 화면의 원격 이동과 발사체

v35의 `Timeline.frame`은 마지막 스냅샷을 실제로 받은 시각마다 재생 시계를 다시 맞췄다. 통상 50ms마다 발생한 스냅샷에 15/40/5/35ms 지연을 순서대로 주자, 등속 이동 중인 상대가 60Hz 화면 540프레임 중 45프레임에서 정지했다. v35.1은 연속된 정상 권위 틱의 예상 도착 시각에 도착 오차의 1/8을 반영한다. 틱 간격이 1~4를 벗어나거나 도착 오차가 75ms 이상이면 실제 수신 시각을 사용한다. 자기 캐릭터 예측, 75ms 재생 버퍼, 장기 단절 시의 150ms 진행 한도와 반사·포탈의 권위 이벤트 처리는 기존 경로를 사용한다.

| 60Hz·동일 입력 재생 | v34 | v35 | v35.1 |
|---|---:|---:|---:|
| 원격 캐릭터 프레임 변위 오차 p95, 월드 단위 | 6.4 | 6.4 | 0.605 |
| 원격 직진탄 프레임 변위 오차 p95, 월드 단위 | 19.2 | 19.2 | 1.814 |
| 정지한 원격 이동 프레임 / 540 | 45 | 45 | 0 |
| 권위 시각에서 화면까지 중앙값 / p95, ms | 90 / 106.67 | 90 / 106.67 | 98.03 / 100.15 |

일정한 20ms 지연에서는 세 버전 모두 변위 오차 0, 재생 지연 95ms였다. 무입력 자기 좌표의 변위도 모두 0이었다. 지터를 완화할 때 중앙 재생 지연은 위 표본에서 약 8ms 늘었다. `node tests/combat/smooth-clock.mjs <소스트리>`로 30·60·120Hz에서 같은 세 지연 패턴을 재생할 수 있다. [v34](../evidence/v35-1/input-clock-v34.json) · [v35](../evidence/v35-1/input-clock-v35.json) · [v35.1](../evidence/v35-1/input-clock-v351.json)

Windows Edge·Canvas balanced·1366×768, 학생과 호스트가 있는 로컬 실제 WS 시험에서는 v35와 v35.1 모두 이동 시작·정지·반전 4개 입력이 서버에 적용됐고, 평타·스킬이 각 1회 발동했다. v35→v35.1의 이동 입력부터 첫 draw까지 범위는 11.0~32.5→22.5~35.8ms, 스냅샷 수신 간격 p95는 92.2→99.4ms, 서버 정지 후 위치 변위는 0→0이었다. 각 1회 관측치로 조작 속도 향상을 단정할 수 없다. v35.1 평타는 포인터를 82.1ms 유지한 후 눌림 시점 기준 84.8ms에 전송, 101.5ms에 접수 ACK, 162.0ms에 실제 탄체 draw가 나타났다. 스킬은 키를 누른 뒤 0.4ms에 전송, 13.9ms에 ACK, 124.3ms에 권위 예고, 516.8ms에 탄체 draw가 나타났다. 서버 자체 시계에서 평타·스킬 접수부터 적용까지는 15.8·2.1ms였다. 테스트 전용 환경변수 `SMOOTHNESS_DIAGNOSTICS=1`과 `node tests/combat/live-control.mjs canvas`로 재현한다. 첫 draw는 캔버스 제출 시각이며 실기기의 화면 출력 지연은 측정하지 않았다. [브라우저·WS 원자료](../evidence/v35-1/input-browser-windows.json)

20명 중 4명이 함께 복귀한 WS 시험은 각자의 신원·입력 바닥값·새 연결 epoch, 이동 좌표, 평타·스킬 시퀀스를 확인했다. 호스트와 다른 학생 모두 네 학생의 탄체 이벤트를 받았고 전원 같은 방에서 결과→재경기에 성공했다. 약 5.90초가 걸렸다. `node --test tests/integration/classroom-group-resume.test.mjs`로 실행한다. 포탈 이후 복귀를 검사하는 Pixi fixture는 동결된 서버 시계를 진행시키기 전에 새 생명의 실제 오른쪽 이동 명령 수신을 확인하도록 고쳤다. 이전 고정 100ms 대기로는 입력 도착을 입증할 수 없었다.

지터 재생 변경만 되돌릴 때는 `apps/client/src/presentation/timeline.js`에서 이번 `clockAt` 추정과 사용을 v35의 `last.at` 기준으로 되돌린다. 저장 데이터나 배포 프로토콜 변환은 필요하지 않다.
