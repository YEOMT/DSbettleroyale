## 비교 조건

동일한 Linux 작업 내 세 버전을 각각 체크아웃한다. 20명과 호스트, 학생 브라우저 두 개에서 같은 시드·맵·입력 절차로 3라운드 진행한다. 개인전과 점령전, Canvas와 소프트웨어 Pixi를 별도로 비교하며 네 경우의 절반에서는 버전 실행 순서를 뒤집는다. 30인 소켓 부하와 동일 입력의 서버 단독 교차 측정을 분리했다. 공유 러너의 브라우저·서버 자원 경합, 실시간 입력 간격 및 GC 차이는 남는다.

`node tests/combat/classroom-compare.mjs v35.1 solo pixi`가 세 버전의 비교를 실행한다. `solo canvas`는 추가로 나머지 4개 개인전 맵을 각 3회, `team-capture canvas`는 서버 단독 교차 시험, `scissors pixi`는 480발, `load30 sockets`는 세 버전의 40초와 작업본의 600초 실제 연결을 검사한다. 컨테이너와 잠금 파일은 기존 Evolution comparison과 같다. 같은 소켓에서 참가자·방을 유지하면서 일부는 새 연결 epoch로 복귀한다. 시간 제한이 있는 점령 모드는 10분 연결 중 결과와 재경기를 거친다. 40초 시험은 같은 매치·증강 난수 시드와 입력 정책을 사용한다. 실제 스케줄링과 참가자가 받는 마지막 스냅샷에 따라 명령 도착 프레임이 달라진다. 공개 산출물에는 합성 참가자의 집계만 담는다.

사용자가 현재 실기기를 사용할 수 없다고 확인했다. 저사양 Android·iPhone과 노트북 호스트의 실제 수업 Wi-Fi, 15/20/25/30명 실기기 단계 부하, AWS 1GB에서의 v35.1 성능은 NOT_RUN이다.

## 30인 점령전 전송과 메모리

같은 Linux 러너의 40초간 실소켓 시험에서 v34 / v35 / v35.1의 서버 CPU는 9.980 / 11.404 / 11.181초, 전체 수신은 616,227,376 / 608,245,639 / 612,815,066바이트였다. step p95는 1.188 / 1.429 / 1.659ms, snapshot p95는 2.565 / 2.984 / 2.874ms였다. 세 실행 모두 과부하 0회였다. 실제 경기의 타이밍을 포함하면 v35.1의 모든 지표가 향상된 것은 아니다.

v35.1 30명과 호스트가 600.023초 동안 실제 소켓을 유지했다. 두 라운드, 같은 방 재경기 한 번, 368,807스냅샷, 10,657,805,202바이트를 받았다. 오류·서버 과부하·교체 스냅샷은 0회였다. 118개 5초 표본에서 전송 버퍼·신뢰 메시지 큐·보류 스냅샷 모두 0이었고 재경기 직후 계측한 전투 객체는 종류별 0이었다. 종료 후 방·피어·토큰도 모두 0이었다. step p95/p99는 1.090/1.559ms, snapshot 2.408/4.711ms, 서버 입력 적용 16.508/18.948ms, 클라이언트의 입력 배치 권위 확인 45.683/46.853ms였다. 마지막 값은 공격 버튼의 화면 응답시간과 별도로 측정한다.

첫 1분→마지막 1분의 서버 RSS 중앙값은 **182.06→265.86MiB**(최고 283.43), 사용 힙 중앙값은 **44.61→62.16MiB**(최고 91.09)였다. 종료 참조 검사와 별개로 10분 동안 메모리가 늘었다. 이 실행에서는 힙 소유자별 생존 객체나 OS OOM 로그를 수집하지 않았다. v34·v35의 600초 결과도 없어 이 증가가 패치에서 발생했는지, 장기적으로 안정되는지는 미확정이다. 원자료에는 버전별 40초 비교와 118개 메모리·큐 표본을 함께 남겼다.
