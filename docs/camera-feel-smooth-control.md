# 관전 카메라·조작·공격 표현 검증

기준 main은 PR #5가 병합된 `ef84ca5e522d06a435fc59d4a0fee07cb56a7b20`이다. 작업 브랜치는 `codex/camera-feel-smooth-controls`다. PR에는 최종 소스 SHA와 해당 SHA의 Actions 결과를 기록한다.

## 재현과 수정

| 경로 | 기준에서 확인한 현상 | 변경과 판정 |
|---|---|---|
| 마우스·버튼 입력 | 실제 Canvas 위 마우스 이동에서 Window의 `getBoundingClientRect is not a function` 예외. 오른쪽 이동 중 평타 버튼 down, 왼쪽 이동 후 release해도 서버로 오른쪽 raw aim 전송 | `controls.js`, `viewport.js`. 현재 canvas의 CSS rect와 논리 카메라를 사용한다. 움직이지 않은 평타 버튼은 release 시 이동 방향, 정지 시 최근 방향을 사용한다. 드래그는 해당 포인터가 소유한다. 실제 왼쪽 발동과 WebGL 손실 후 새 Canvas의 마우스 목표·터치 해제 확인 |
| 자기 위치 | 10단위 보정 뒤 100ms에 30/60/120Hz에서 5.12/2.62/0.69가 남았다. 같은 시각을 재조회해도 또 줄었다 | `timeline.js`. 수신 시각 기준으로 기존 60fps 감쇠를 적용해 모두 2.62144가 남는다. ACK와 history를 유지하며 생명·warp·사망·큰 오차는 즉시 맞춘다. 자기 카메라는 표시 몸체에 붙이고 최대 36단위의 시선 이동만 100ms 시간 상수로 완화한다. 원격 보간 지연 4.5틱(75ms)은 유지했다 |
| 관전 | 인원 구간이 카메라 정책을 바꾸고 학생 집중이 첫 참가자를 따라갔다 | `camera.js`, `renderer.js`, `ui/app.js`. 전체 관전은 생존자·HUD 여백으로 구도를 결정한다. 전투 집중은 확정 접촉과 접근 중인 공격으로 교전 쌍을 고른다. 평가는 180ms 간격, 유효 교전 유지 1,200ms, 경쟁 교전 전환에는 25% 우위를 사용한다. 사망·교전 종료 시 해제한다. 줌인은 인원·모드 변경 뒤 240ms 대기 후 430ms 시간 상수로, 줌아웃은 90ms로 따라간다. 점령전은 고정 전장과 A/B/C를 유지한다 |
| 발사·피격 | 기존 근접 step은 이미 서버가 적용했다. 화면 보정과 단일 몸체 표현만으로는 전진과 타격 성격이 잘 드러나지 않았다 | `attack-pose.js`와 두 렌더러의 몸체 그리기. 확정 공격의 소유자·생명·종류·seq로 한 번만 연출한다. 저격은 예고 종료 후 발사에 맞춰 최대 4 CSS px 또는 화면 반경의 15% 이내에서 120ms 동안 복원한다. 피격 방향은 서버 접촉 사건에서 얻는다. 몸체 변형은 조준·총구·충돌에 사용하지 않는다. reduced-motion은 장식을 끄고 기본 피격·위험 표시를 유지한다 |

로컬 연속 전투에서는 늦은 첫 화면이 짧은 몸체 변형을 통째로 놓쳤고, 새 생명의 피격 사건을 이전 생명의 보간 프레임이 지우는 경우도 재현했다. 최근 사건만 첫 유효 표시 프레임에 맞춰 복원하고 유효 범위를 넘긴 사건은 폐기한다. 저격 예고 marker가 실제 탄보다 먼저 반동을 소모하던 중간 구현도 수정했다. 낙뢰 착지 시험은 기존 서버 엔티티 이름 `warning`을 확인하도록 고쳤다.

첫 원격 CI에서는 소프트웨어 Pixi의 1366×768 프레임 간격 p50이 433ms여서 타이머가 두 번의 이동 전환을 샘플링하지 못했다. 입력 상태가 바뀌고 정상 60Hz 주기가 이미 경과했을 때만 한 스텝을 빌려 즉시 전송하며, 다음 interval의 중복 예측을 차단했다. 연속 시험은 첫 실제 표시를 받은 뒤 다음 키를 놓아 각 전환의 표시·서버 적용을 모두 검사한다. Pixi 연속 조작 fixture의 viewport는 800×520이다. 첫 Canvas 마우스 시험도 서버 큐 대기에서 실패해 실제 쿨타임·100ms 재입력 조건·큐 ACK를 기다리도록 했다. 후속 원격 Pixi에서는 네 전환이 표시·서버 적용됐고 6종의 세 화면 검사를 마쳤다. 재경기 검사에서 첫 학생이 로비에 도착한 순간 다른 소켓의 이전 경기 자원을 읽어 61개가 남은 것으로 집계됐다. 세 화면 모두 새 matchId의 LOBBY를 받았을 때 검사하니 로컬 잔류 sprite·texture·pose는 각각 0개였다. 팀 생존 E2E에서는 결과와 순위까지 표시된 뒤 재경기 버튼을 누르는 시점에 60초 한도를 초과했다. 교사·공격자 viewport와 스크린샷을 유지하고 세 번째 Pixi 참가자의 viewport를 680×480으로 설정했다. 모드 토글 조작은 같은 검사를 수행하는 연속 전투 job에서, 점령전 고정 이유는 E2E에서 확인한다. 이전 실패를 최종 HEAD의 결과와 구분한다.
