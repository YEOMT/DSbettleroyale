## 3. 이동속도 및 공허 파괴자

### 3.1 다음 3종만 기본 속도 개선

| ID | 캐릭터 | manifest상 기존 speed | 지정 목표 speed |
|---|---|---:|---:|
| `emoji-139` | 좀비 | 1.00 | **1.18** |
| `emoji-028` | 아이언월 | 1.14 | **1.27** |
| `emoji-007` | 폴아웃 | 1.20 | **1.30** |

**중요 구현 주의:** 좀비의 실제 걸음 속도는 단순 `p.speed`만 사용하지 않고 `packages/engine/src/combat/player-input.js`의 `brBaseWalkingSpeed`에서 `BR_V29_ZOMBIE_WALK`를 별도로 반환한다. **`manifest.speed`만 수정하고 실제 움직임을 안 바꾼 척 성공 보고하면 안 됨.** 목표는 실제 서버 이동속도에서 약 18% 체감 상향이다. 코드 경로에 맞춰 `BR_V29_ZOMBIE_WALK`를 조정하거나 더 명확한 단일 속도 경로로 통합하고, 기존 특수 보정이 두 번 중첩되지 않게 한다.

아이언월과 폴아웃 역시 `brBaseWalkingSpeed`가 `Math.max(5.6, p.speed*4.05)`와 역할별 보정 등을 사용하므로 **실제 초당 이동거리와 대시/버프 미적용 조건에서의 이동 계측**을 기준으로 결과를 확인한다. 그 외 저속 S급 캐릭터 전반에 일괄 하한 적용 금지.

## 6. 신규 B급 `🚦 신호등` — 스킬 「빨간불!」

- 기본 공격: 평범하고 가벼운 **직선 신호탄 1발**. B급 평균 기본 공격 예산으로 시작하되, 화력보다는 이동 심리전이 핵심. 새 투사체 시각 자산을 대량 만들지 않고 기존 기초 발사 로직 사용.
- 고유 스킬 초기 목표: **전방 160° 부채꼴(반각 80°), 사거리 780, 0.6초 예고, 발동 순간 실제로 이동 중인 적에게 이동속도 65% 감소를 1.8초간, 쿨타임 17초, 직접 피해 0**.
- 예고 동안 움직임을 멈춰 피하는 플레이 가능: 서버가 예고 시 대상 목록을 미리 고정하지 않고 **확정 발동 프레임의 실제 이동 의도와 이동 상태**로 판단. 입력이 거의 0(자연 미세 떨림/잔여 속도)인 플레이어는 `정지`로 판정하는 데드존/임계치 마련. 네트워크 수신 지연이 움직임 판단을 무작위로 뒤집지 않도록 권위 입력 기준·스냅샷 테스트.
- 발동 순간 범위·벽 차단 검사, 팀원/사망자/불법 대상 제외. 이미 수행 중인 돌진이나 강제 넉백을 억지 취소하지 않고 **일반 걸음/이동속도에만 둔화** 적용. 기존 둔화와 무제한 곱셈 중첩 금지.
- 손쉬운 식별: 예고 범위가 선명하되 0.6초 동안 과도한 펄스·화면 흔들림/커다란 텍스트 없음. 맞은 플레이어의 아이콘·짧은 효과만 표시.
- 이름/이모지/스킬 수치·한국어 설명·카드·도감·분류·확률 등 모든 소스 생성물 반영. 84종 활성 로스터 검증. 신규 F급 캐릭터는 이번 범위에 없음.

## 7. 보급 개편: 기존 XP 유지 + 전투 보급 3종 반복

### 7.1 현재 코드 상태와 보존

- 현행 `world.js`는 `supplyDropSpawnFrame=1050~1750`프레임의 **경기당 1회 XP 특별 보급** `supplyDropSpawned`를 사용하며, `farm/resources.js`의 `SupplyDrop`은 착지 후 성장 모드에서 **XP +2**(기존 부가 효과 포함)를 부여한다. 이것과 **일반 농장 XP·회복 상자(기존 정기 웨이브)**는 서로 다른 시스템이다.
- 사용자 요구: **기존 XP 보급의 보상과 일반 XP/회복 상자 생성은 그대로 유지**하고, 특별 XP 보급 자체는 후반에도 반복 등장. 새로운 전투 보급은 특별 XP 보급보다 더 자주 등장.
- 솔로 개인전에서만 적용 시작. 팀 점령/팀 킬배틀/팀 생존전은 기존 규칙을 보존하며, 새 보급·메시지의 예외가 모드별로 뒤섞이지 않게 한다.

### 7.2 보급 출현·선점·수명

| 구분 | 첫 등장의 원칙 | 반복 간격 | 동시에 존재할 수 있는 수 | 보상/특징 |
|---|---|---|---|---|
| 기존 특별 XP 보급 | 기존의 약 17.5~29초 최초 타이밍 유지 | **75초마다** | XP 보급 최대 1개 | **XP +2** 및 기존 획득 처리 유지 |
| 신규 전투 보급 | 약 25초 전후 최초 등장 | **25초마다** | 전투 보급 최대 1개 | 세 종류 중 1종, 10초 버프 |

- 스케줄은 **호스트 권위 시뮬레이션 시간**을 기준으로, pause·복귀·재경기 후 중복 출현/타이머 유실이 없어야 한다. 보급이 여전히 남아 있으면 동시 2개로 쌓지 않고 **기존 것의 수명 종료 또는 회수 후 다음 등장** 처리(그 과정에서 무한 지연되지 않도록 만료 상한).
- 신규 전투 보급의 종류는 세 가지 `🔥 공격 / 🌪️ 질풍 / 🛡️ 방어`. **무작위로 번갈아** 나오되 동일 종류의 연속 중복은 가능한 한 피하고(직전 종류 제외 2종 중 균등 선택), 고정된 3종 순환만 반복하지 않는다. 공정성 검증을 위해 RNG 시드와 등장 로그가 재현 가능해야 한다.
- 각 전투 보급은 **착지 전 3초 동안 작은 지면 예고**와 미니맵 아이콘을 보여준다. 착지 전 획득/투사체 충돌 불가. 착지 후 최대 **12초간** 유지한 뒤 미획득 시 사라지고, 플레이어 **첫 1명만 획득**한다.
- 보급 오브젝트 **현행보다 화면상 약 25% 확대**(타입 별 색/이모지 차별화). 판정 반경은 25% 전부 확대하기보다 픽업 편의성에 맞춰 소폭(예: +10~15%) 증가; 상자/엄폐 충돌을 새로 만들어 이동 장애가 되게 하지 않는다. 비용 낮은 정적 그림·이모지 캐시 우선.
- XP 보급과 전투 보급은 각 1개씩 존재 가능. 월드의 기존 `supplyDrop` 1개 구조를 무리하게 공유하지 말고 별도 `combatSupply` 상태를 둘지, 명시적 구분된 소수 엔티티 컬렉션을 둘지 결정하여 **모드·사망·재경기 reset** 보장.

### 7.3 버프 상세 (각각 10초)

| 보급 | 아이콘 | 적용안 | 전제 |
|---|---|---|---|
| 광폭 보급 | 🔥 | **직접 공격 피해 ×1.45** | 평타+직접 스킬 피해만. 독/출혈/지속 피해/장판/포탑·소환체/환경 피해에 중복 곱 금지 |
| 질풍 보급 | **🌪️** | **일반 이동속도 ×1.45** | 고유 대시·순간이동·강제 이동 속도는 유지. 속도 버프 상한 및 조합 검증 |

### 7.4 최후반 자기장 내부에 지속 낙하

- **생존자 2명까지** 위의 반복 보급 스케줄 계속 운영. 최종 3인 버닝 기능과 충돌·중단하지 않는다.
- 안전 위치는 `ringGeometry`의 **현재 중심/반경이 아니라 착지 시점에 예측되는 중심/반경**을 사용해 검사. 자기장·벽·상자·포탈·가속 발판·유효 지형·플레이어 충돌을 확인하고, 픽업 가능한 접근 길(막다른 벽 속 등)을 보장.
- 중간에 자기장이 압축되어 예고 위치가 위험해지는 경우 **도착 전 안전한 위치로 재계산**하고 위치·예고를 동기화하거나 해당 웨이브를 합리적으로 취소. 예고한 곳과 실제 착지가 다르다면 모든 클라이언트 동기화 보장.
- 자기장 반경이 너무 작아 보급의 실제 본체/안전 여유/접근 경로를 확보할 수 없는 경우에는 **생성 건너뛰기**. 자기장 밖에 생성하거나 좁은 링의 중앙에 강제 겹치기/즉시 안전 판정 해제 금지.
- 고정 시간/객체 상한·기존 스냅샷 활용, 특별한 WS 메시지 추가 전송은 이벤트 발생 시만. 서버 호스트 1GB RAM, 20인 동시 접속 기준 성능 부담 상한 유지.

## 8. 전원 공통 아나운서: 킬·보급·결전 메시지

### 8.1 메시지 내용 및 의미

학생과 교사 호스트 모두 볼 수 있게 하고, **기존 작은 킬 피드는 보존**하되 그 위에 중요 이벤트만 잠시 떠오르는 아나운서 띠를 추가한다. 플레이어의 실제 이름을 토대로 표시하되 클라이언트에서 `textContent` 등 안전한 텍스트 처리를 사용하고 임의 HTML로 삽입 금지.

| 조건 (공식 서버 판정) | 메시지 예시 | 우선순위 |
|---|---|---|
| 경기 첫 **유효한 플레이어 처치 1회** | **FIRST BLOOD! · {이름}** | 높음 |
| 같은 경기에서 누적 3킬 최초 도달 | **{이름} is on a killing spree!!** | 보통 |
| 누적 5킬 최초 도달 | **{이름} is unstoppable!!** | 보통 |
| 누적 7킬 최초 도달 | **{이름} is legendary!!** | 높음 |
| 누적 10킬 최초 도달 | **Who can stop {이름}?!** | 높음 |
| 전투 보급 출현 예고(3초 전) | **🌪️ 질풍 보급 접근!** (종류별 치환) | 보통 |
| 보급 획득(관전 포함) | **{이름} 획득: 🔥 광폭!** | 낮음 |
| 최종 3인/자기장 중요 압축 | 기존 결전 알림을 아나운서와 조화롭게 유지 | 최상 |

- `3킬 이상`이라는 기준은 **동일 경기 누적 킬**(6초 내 연속처치 등 짧은 기간 기준이 아님). 각각의 임계치 **최초 1회만** 표시. 4·6·8·9킬에는 같은 문구 반복 금지. 새 경기에서는 초기화.
- `FIRST BLOOD`는 실제 플레이어가 다른 플레이어를 유효하게 처치한 첫 사건만. 자기장·자해·환경 사망·친선팀 처치는 제외. 중복 사망/중복 콜백·동시 처치의 결정적 순서 보장.
- 팀전은 기존 점령전 상단 정보·팀전 피드/리스폰을 유지. 같은 기준을 적용하되 승리·점령 공지는 킬 멘트보다 우선. 팀 부활 모드에서는 재부활해도 **해당 경기의 누적 킬은 유지**하며 한 번 받은 임계치 보상은 반복하지 않는다.
- 우발적인 악용 방지: 이름 공백/제어문자/과도한 길이/특수문자 제거·길이 제한, 외부 접속에서 텍스트 무결성 검사. 공격자 없는 피해를 최근 공격자에게 임의로 돌려 킬 알림으로 만들지 않음.

### 8.2 UI·전송·가시성·접근성

- **모든 참가자의 전투 UI와 교사 호스트에 표시**. 관전 전용 메시지가 학생에게 전달되지 않는 기존 `presentation` 분기 확인. 현재 `getVisibleState`가 `presentation`을 공용 상태로 전달하는 경로가 있어 이를 활용 가능.
- 화면 중앙을 덮는 큰 팝업 금지. 상단 HUD 아래 또는 사용 가능한 가장자리에 **높이 약 28~40 CSS px의 반투명 한 줄 배너**, 1.8~2.2초 표시 후 부드럽게 사라짐. 모바일 390×844에서도 이동/공격/스킬 버튼, 체력, 미니맵, 점령전 점수/거점 상태를 가리지 않아야 함.
- **고정 우선순위 + 재생 제한**: 현재 표시 중인 높은 우선순위 메시지는 낮은 우선순위 보급 획득 공지가 가로채지 않음. 중간 우선순위 2~3개 발생 시 최대 3개만 큐에 두고 오래된 낮은 순위를 폐기. 1초마다 여러 UI 토스트 쌓는 방식 금지.
- 서버는 타입/플레이어ID/현재 스코어/고유 이벤트 seq/권위 frame 중심의 **변경 시점 이벤트만 생성**. 화면 문구를 매 틱 문자열로 새로 빌드하고 지속 방송하지 않음. 20명의 학생용 개별 배너 전송을 만들어 네트워크를 증폭하지 말고 기존 공유 스냅샷에 bounded event state를 얹기.
- 새 이벤트는 중복 표시/재접속 후 과거 사건 재생/리매치 격리와 정확한 순서를 보장. 학생이 시점 밖에 있더라도 전체 아나운서는 전원에게 보여야 함. 개인 프라이버시가 필요한 위치·은신 정보는 포함하지 않는다.
- 실시간 대화/채팅 기능을 구현하라는 요청은 아님. 유저가 자유 텍스트를 보내는 기능은 이번 범위 밖.
- 기존 알림음은 과하지 않게 우선순위 높은 일부 사건만 짧게 재사용. 자동재생 제한, 음소거, 접근성 `aria-live="polite"`, 저사양/동작 줄이기 설정 준수. 화면 흔들림·추가 파티클은 없음.

### 8.3 기존 코드 연결 지점

- `packages/engine/src/world/world.js`: `firstBloodDone`, `eventFeed`, `pushCombatEvent`, `registerKillEvent`, `announce` 기존 존재. 현재 `registerKillEvent`는 첫 피를 표시하지 않고 평범한 `eliminated` 텍스트만 추가한다. 이를 재활용하되 기존 사망/피드/팀전 규칙을 유지할 것.
- `packages/engine/src/index.js`: `presentation`의 `announcement`/`feed`, `getVisibleState` 공유 경로를 검토; 서버 `apps/server/src/ws/snapshot.js` 공용 직렬화 캐시를 보존.
- `apps/client/src/ui/app.js`: 지금 호스트에는 `br-host-headline`과 `br-host-feed` 표시가 있으나 학생 공용 큰 킬 아나운서는 없다. 공용 UI를 적용하면서 기존 호스트 HUD와 점령 공지 충돌 방지.

## 9. 호스트 ‘전체 관전’의 화면 중심 보정

- **먼저 실제 원인을 확인:** `apps/client/src/render/camera.js` `HostCamera.update()`는 솔로/팀 생존전 `overview`에서 살아있는 캐릭터들의 bbox로 중심 `(left+right)/2,(top+bottom)/2`를 구한다. 그러므로 모든 캐릭터가 한쪽에 몰리면 전장 자체보다 카메라가 치우쳐 보일 수 있다. 점령전은 `this.x=this.y=0` 가정과 상단 고정 `top=126`이 적용된다. `renderer.js`의 `pose.screenX/screenY`, `hostInsets()`와 CSS HUD도 실제 보이는 화면 중심에 영향을 준다.
- 목표: 호스트 **전체 관전**은 전장의 실제 지형 중앙/활성 안전 구역(솔로) 또는 실제 경계의 기하학적 중심(점령전)을 기준으로 화면의 **HUD를 제외한 가용 영역 중앙**에 자연스럽게 배치. 화면 중앙 `50%,50%` 고정으로 HUD 아래 내용이 잘리는 방식 금지.
- 솔로는 월드 원점과 자기장 중심이 같다는 가정 금지. **자기장/맵의 실제 중심, 현재 위험구역 반경, 살아 있는 캐릭터의 위치를 함께 고려**해 전체 게임이 잘 보이고 빈 공간이 과도하게 많지 않게 하고, 추적 모드의 기존 전투 집중 자동 카메라는 보존.
- 점령전은 `0,0` 하드코딩보다 `(boundary.minX+maxX)/2,(boundary.minY+maxY)/2`를 사용하고 2·3·4팀 X지형과 점수판 상단 여백을 고려해 실제 중앙 정렬. X지형/거점 A/B/팀 베이스가 화면 밖으로 잘리지 않아야 한다.
- 종횡비(16:9, 4:3, 390×844), 모바일 브라우저 시각 viewport, 음악/점령 HUD ON/OFF, `Pixi`/`Canvas` 경로 각각 캡처 비교. **카메라 디스플레이 좌표만 수정**하고 참가자 물리·사격 조준·실제 월드 중심/스폰 위치는 변경 금지.
- 마지막 3명 관전이 일부 끊기는 기존 병목을 이번에 전면 재작성하지 말 것. 부수적 개선은 허용하되 이번 우선순위는 **전장 중심·가독성**이다.
