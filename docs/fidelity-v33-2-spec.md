# DSbattleroyal v33.2 — v32.1 원본 완전 보존 감사 및 기능·화면 복구 명세

## 0. 목표와 작업 원칙

**핵심 목표:** v33.1의 Node/WebSocket 서버 권위 아키텍처와 성능 개선은 유지하면서, 사용자에게 보이는 게임의 화면·카메라·조작·음향·절차·효과·타이밍을 기준 원본 v32.1과 가능한 한 정확히 일치시킨다. 새 디자인을 만드는 작업이 아니라 **원본 fidelity audit + 누락 복구**다.

현재 수업 테스트에서 확인된 증상: (1) 배경음악이 들리지 않음, (2) 퀴즈 제한시간 표시가 사실상 사라짐, (3) 호스트 관전 화면의 동작/외관이 원본과 다름, (4) 호스트 자동 줌/관전 카메라가 원본처럼 동작하지 않음, (5) 그 밖에도 아직 발견하지 못한 미묘한 차이가 다수 의심됨.

- **작업 기준 브랜치:** 최신 `main`에서 새 수정 브랜치를 만들고 현재 코드를 다시 검사할 것. 이 명세 작성 당시 main은 v33.1 PR #2 병합 커밋 `9619942fb55eb5a96c9d6fea69f76fc99d12bbf0`이었음. 실행 시 원격 최신 SHA를 재확인.
- **기준 원본:** `legacy/v32.1/index.html` (원본 root `index.html`과 byte-identical 확인됨). `docs/baseline.md`에 기록된 기준 blob `4e6845b4565170ee2c84e75c0eee5dcc4f98ceac`, SHA-256 `a006aa596c5640ffe127774f271fce7afce81a4769525979fa453f9107ac5d36`, 약 1.36 MB, active 77종.
- **기존 인계 지도:** `docs/source-map.json`, `docs/fidelity-repair.md`, `docs/fidelity-evidence/`, `docs/acceptance.md`를 모두 읽고 기존 수정 성과를 보존할 것.
- 원본 HTML의 최종 실행 상태는 여러 스크립트/후속 덮어쓰기에 따라 결정되므로, 함수 하나를 찾아 복사하는 것으로 끝내지 말 것. 마지막 정의/실제 콜 사이트와 런타임 동작을 기준으로 할 것.
- **금지:** 재설계/그래픽 미화/밸런스 조정/판정 변경/신규 시스템 추가/원본 Firebase 재활성화/서버 권위 구조 해제. 원본 HTML을 그대로 iframe에 임베드하거나 동작 중인 서버를 건너뛰는 임시 해결도 금지.
- 로컬 소스 수정 및 브라우저 테스트→별도 브랜치 commit/push→PR 생성까지. **main 자동 병합, AWS 배포/재시작, `.env`·암호 변경, 외부 운영 게임 수정 금지.** 학교의 현재 20명 테스트를 중단시키지 말 것.

## 1. 최초 작업 — 원본 대비 기능 목록 작성 (증상 두세 개만 패치하고 완료 선언 금지)

## 2. 호스트 관전 카메라 — 최우선 복구

### 확인된 구체적 차이

원본 v32.1에는 생존자 위치의 min/max bounding box를 구하고 중앙을 바라보며 자동 배율을 조절하는 카메라가 구현돼 있다. Pixi 호스트 경로 `brPixiHostFrame`과 Canvas `GameWorld.draw`에 대응 코드가 있음:
- 일반/브로드캐스트: 생존자 위치의 범위를 계산, 여유값은 일반 400, 브로드캐스트는 생존자 <=2일 때 230, 그 밖에는 290.
- 목표 zoom은 화면 가로·세로 치수에 따른 fit 값을 사용하며 대략 최소 0.22, 최대 1.5/1.55/1.78 제한 (조건별 원본 정확한 식을 확인할 것).
- 시선 이동과 줌에 easing 적용. Pixi 경로는 broadcast focus ease 약 `.032` / scale ease 약 `.022`, 일반 `.05/.03` (프레임 레이트 의존 여부 및 Canvas 구현을 함께 확인).
- '카메라: 전체/학생 집중' 토글은 원본 비점령 모드에서 동작하며, 학생 집중 목표 스케일은 1.12.
- **점령전은 예외:** 원본 `brCaptureViewPort`는 상단 HUD 여유 공간(top 약 min(126, h*0.22)), 아래 여백 48, 좌우 여백 24를 확보해 전체 경계를 화면에 맞추고 위치를 중앙 고정한다. 원본 `br-focus-toggle`은 `brCaptureMode()`일 때 아무 동작도 하지 않음. 점령전에 억지로 학생 자동 줌을 적용하는 것은 원본 복구가 아님.

반면 현 v33.1 `apps/client/src/render/renderer.js`는 대체로 맵 전체 fit 고정 또는 최고 킬 생존자 1명 추적으로 단순화됐으며, 이전 방식의 생존자 분포 기반 동적 자동 줌과 easing이 없음. 기존 `renderer.focus` 토글은 원본 `focusPlayer`와 똑같지 않다. 해당 코드를 실제 렌더 경로 기준으로 수정해야 한다.

### 구현 지시

- 모드별 원본 카메라 정책을 client-only 모듈로 분리(`camera.js` 등 가능)하고 server authoritative snapshot의 실제 actor alive/pos와 map bounds를 입력으로 사용.
- 개인전·팀 생존전: **인원 감소→생존자 분포 축소→방송 화면이 자연스럽게 줌인**, 분포 확대→서서히 줌아웃. 갑작스런 딱딱한 점프 금지. 게임 종료/집중/충돌 관련 원본 분기를 점검.
- 점령전: 원본처럼 UI 영역을 예약한 전체맵 관전, 거점 HUD·레이블·점령 팀 점수/순위/타이머를 정확히 위치시킬 것. 집중 토글의 노출/무효 상태도 원본과 일치시킬 것.
- 호스트 캔버스와 Pixi에서 동일한 카메라 정책; CSS 캔버스 크기, DPR, 프로젝터 16:9/4:3 화면도 확인. 카메라가 HUD를 덮지 않도록 하고, 벽/캐릭터가 화면 경계 밖으로 잘리거나 개체가 너무 작게 고정되는 문제를 검사.
- 원본의 이벤트 포커스/최종 2명 상황/경기 종료 시점 등 조건별 동작을 조사. 서버 스냅샷에 이벤트 포커스에 필요한 데이터가 없다면 정확히 어떤 프로토콜 필드가 누락됐는지 밝히고 **게임판정과 분리된 최소한의 표시 전용 데이터**만 도입. 확인 못한 기능은 보존 완료로 표기하지 않음.

## 3. 배경음악과 퀴즈 타이머 — 명백한 회귀

### 음악
- 현 `apps/client/src/audio/audio.js`는 `enabled=false`로 시작하고 `play()` 실패를 `catch(()=>{})`로 삼킨다. 단순 볼륨 변경/버튼 표시만으로 모든 재생 문제를 해결한 것으로 보고하지 말 것.
- 원본 v32.1의 실제 기본 음소거 정책, 버튼 문구, 시작 이벤트, 단계별 BGM ready/start/final 전환·반복, 볼륨 복귀, 화면 hidden/focus, 원래 음악 소스와 체감 동작을 대조.
- autoplay 정책을 우회하려 하지 말고 사용자 제스처 이후 재생을 복원하고, 파일 URL 접속·반환 MIME·CORS/리다이렉트/오디오 오류·play() reject를 진단 화면과 테스트 로그에 구분 표시. 외부 음원 파일을 바꾸거나 새로 제작하지 말 것.
- 음악 기본 정책이 원본과 다르면 '복구했음'이 아니라 구체적인 차이로 기록하고 사용자 승인 없이 정책 변경하지 말 것.

### 퀴즈 제한시간
- 현 서버 `apps/server/src/rooms/room.js`는 `quizEndsAt=manager.now()+quizSeconds*1000`로 관리하고 `RoomManager.sweep()`이 QUIZ 종료 시 DRAFT로 전환함. 서버 규칙이 삭제된 것은 아니나 실제 WS 20명에서 45/60/90초를 검증할 것.
- 현 UI `apps/client/index.html`의 `#br-quiz-timer`는 `<div ...><span>60</span></div>`, `#br-host-clock`은 초기 `br-hidden`. `apps/client/src/ui/app.js`는 `text('br-quiz-timer', left)`로 **span 요소까지 통째로 대체**하고 `#br-host-clock`의 숨김 해제를 하지 않는다. 위계와 원형 진행률(`--br-progress`)까지 정확히 연결해야 함.
- 클라이언트는 서버 권위 퀴즈 종료시각/남은 시간을 기준으로 표기하고 UI 재렌더·연결 복구·페이지 숨김 후 복귀에서도 타이머가 리셋되거나 늘어나지 않을 것. 필요하면 서버의 절대 end timestamp와 시계 오프셋 이용; 기존 서버 종료 규칙을 클라이언트로 옮기지 않는다.
- 학생·호스트 모두 45/60/90초 카운트다운이 화면에 보이며, 만료 후 자동으로 DRAFT로 전환되는 WebSocket E2E 증거 확보.

## 4. 화면·UI·연출의 전수 복구

- **화면별 차이표**: 홈/로비/퀴즈/배정/전투(개인전·팀 생존전·점령전, 학생·교사)/사망·부활/결과·시상·재경기/백그라운드 복구.
- 데이터 텍스트뿐 아니라 DOM 구조/CSS/폰트 크기/컬러/정렬/패널 위치/거점 상태/지도 연출/킬피드/랭킹/이름·레벨·스턴·버프 표시/효과음·음악 토글 표시까지 비교.
- **원본 기능을 통째로 생략한 v33.1 컴포넌트**(예: 호스트 HUD, 킬피드, 카메라, 원래 피격 표시, 최종 상황 포커스)를 찾으면 실제 구현을 연결. `original.css`/`original-painters.js`를 복사만 해놓고 호출하지 않는 방식 금지.
- v33.1에서 이미 고친 증강 카드 `effect/detail`, 비활성 스턴, 탄환 ordinal, 위치 보정 등은 회귀하지 않도록 테스트 고정.
- 브라우저 출력은 동일 해상도(1920×1080, 1366×768, 모바일 세로/가로)와 동일 입력·가상 시간·픽스처에서 캡처. 원본 v32.1은 실제 브라우저에서 외부 Firebase 요청/쓰기 없이 격리 실행하는 레퍼런스 하네스 사용. 현재 구현은 실제 WS를 통해 동일 시나리오로 검증.
- 성능을 이유로 원본 기능을 조용히 삭제하지 말 것. 비용이 큰 렌더는 수치·시각 기준을 유지하며 캐싱·풀링·LOD·품질 옵션으로 최적화; 빠진 내용은 사용자 승인 전 임의로 단순화 금지.

## 5. 반드시 수행할 테스트와 인수 조건

1. 빌드·정적 경계·기존 단위/통합/실WebSocket E2E 전체 PASS; 기존 v33.1 테스트 수 감소 금지.
2. **카메라 정량 테스트**: 20명 흩어짐 → 10명 → 4명 → 2명 → 1명, 각 단계별 v32.1 렌더 중심/zoom 추세와 부드러운 전환 비교, 일반/브로드캐스트/집중/점령 모드 분리, Canvas/Pixi 일치. 첫 20명부터 항상 전체맵 고정인 경우 실패(비점령 기준).
3. **관전 캡처**: 16:9 대형 호스트, 4:3 프로젝터, 점령전 전체맵 UI 여백, 팀별 점수와 경기 시간·킬피드·순위 팝업·카메라 버튼이 화면 밖/다른 패널 뒤로 숨지 않는지 직접 검증.
4. **음악**: 최초 화면·사용자 클릭 후 정상 재생, 단계를 넘기는 ready/start/final 전환, 음소거/볼륨, 외부 파일 실패 메시지, 브라우저별 autoplay 제한을 분리해 검증. 파일 로드 실패가 나면 PASS 아님.
5. **퀴즈**: 45/60/90초 학생·교사 가시적인 숫자와 원형 진행률, 정답/오답/잠금, 만료 DRAFT 전환, 초단위 실제 서버 제한 준수, 재접속 후 타이머 연장/리셋 없음.
6. **20명 수업 검증**: 교사1+학생20, 같은 학교 Wi-Fi로 실제 시험(현장 결과 미확보 시 UNVERIFIED). 부하 자동 시험은 최소 10분, 20Hz 스냅샷 간격·게임 60Hz·overload pause·메모리 사용·CPU step p95·브라우저 frameMs p95·RTT p95·위치 보정 및 투사체 끊김을 구분 측정. 실기기 모바일 터치 포함. 26/30명 10분 기존 과부하 이슈는 덮지 말 것.
7. **결과·재경기**: 퀴즈/배정/경기/시상/재경기, 5회 반복 시 상태 누적·이전 스턴·이전 증강·이전 입력·이전 카메라 추적이 새 경기에 남지 않음.
8. **정확성**: 77 캐릭터/등급·기본HP·속도·평타/스킬·성장 XP/레벨·왕귀·모드 규칙은 기존 baseline 수치 그대로, Firebase 호출/외부 서버 권위/게임 판정 클라이언트 이전 없음.
9. **증거**: 항목별 `PASS / DIFF_FIXED / BY_DESIGN(explained) / PARTIAL / FAIL / UNVERIFIED` 로그, 원본/수정 후 나란히 스크린샷, 입력·프레임·줌·화면 영역 trace, 실제 브라우저 동작 녹화 또는 순서별 캡처, 최종 CI 링크를 PR 설명에 포함.
