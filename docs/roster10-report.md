Canvas145–147은 순차 실행에서 통과한 뒤148의 사거리 밖 fixture가 실패했다. 대상 위치를 각 캐릭터의 실제 반경 밖 근접 거리로 수정하고148–150만 재실행했다. 초기 파일을 뒤 실행이 덮어써145–147의 개별 원시 JSON/시간은 보존하지 못했다. 최종 CI의 전체10 실행을 별도 증거로 삼으며, 이전 시도의 전체 통과로 기록하지 않는다. 이제 선택 실행 파일명에 ID를 포함한다.

실제로 재현·수정한 오류는 링 생성 시 둘 이상의 몸체를 같은 공간으로 분리하던 문제, 연막 미끼의 별도 가시성 누락, 본인 짧은 밧줄의 snapshot 시간 불일치다. 밧줄 재검사는 실제 서버 데이터를 받은 본인/상대/호스트 화면에서 통과했다. 고정 장면 캡처는 조작감이나 연속 성능의 증거로 사용하지 않는다.

초기 콘텐츠 생성에서 브라우저 전용 메타데이터가 엔진에 없던 문제는 보존된 역사/표시 입력과 실제 현재 런타임 수치를 분리해 수정했다. 생성 검사는 원본77의 미승인 차이를 계속 단언한다. 소수점 연산의1e-12 이하 직렬화 차이만 원본으로 정규화하며 승인 수치 변화는 숨기지 않는다. npm 별칭이 PATH에 없어 빌드는 동일한 `node tools/build.mjs`로 실행했다.

## 성능 조건 및 남은 확인

실제 Lightsail 사양은 사용자가 확인한2vCPU/1GB RAM/40GB SSD다. Docker CPU/메모리 제한은 조회하지 못했다. 아래 시험은 이 Windows PC의 loopback이며 AWS 자원 제한이나 실제 교실 Wi-Fi 복제라고 주장하지 않는다. 실물 기기 시험은 이번에 수행하지 않았다.

최종 콘텐츠 hash: `fd780afb06e75dfb6dab229bc5fbc1a1ae5bfedf7cd6eff688dd41bdf3ce7e68`. buildId 일치 검증을 유지한다. 이 작업은 배포하지 않았으므로 기존 AWS/공식 Pages 주소에는 적용되지 않았다. 사용자가 PR을 검토·승인한 뒤 기존 ReleaseOps의 정확한 releaseId 클라이언트/서버 쌍을 후보 환경에 배포하고, 별도 승인 후 정식 반영한다. 롤백 역시 이전 쌍을 선택하며 admission을 검증 전에 열지 않는다.

30연결 최후반은 정지 시간을 제외한 실제 시뮬레이션이 **461.8초**였고,600초 충족 assertion에서 실패했다.성공한600초 전투나 재경기로 기록하지 않는다.객체 표본 peak는3개(분신1/버섯1/독1/링1·16조각의 개별 최대치),서버 RSS peak259.95MiB,이벤트 루프 max1001.39ms,GC max134.26ms였다.각 구간의 실제 draw 간격 p95는약16.8~33.4ms였으며 서버 정지 때문에 화면 진행이 멈추는 문제를 이 평균으로 가리지 않는다.최종 rooms/tokens/peers는0이다.해당605초 실행을 다시 반복해 좋은 결과만 고르지 않았다.**T10.C 미달과 초기20인 실패의 원인은 미확정이므로 전체 안정화 완료·운영 배포 준비 완료를 선언하지 않는다.**

측정 PC는Intel i5-1340P/논리16CPU/Windows10.0.26200/RAM15.57GiB이며 도중 여유 RAM2.61GiB였다(CIM 조회는 권한 제한으로 실패,Node OS 조회).실제2vCPU/1GB Docker 제한 시험은 NOT_RUN이다.

실시간 증거는 artifacts/roster10/live/attacker-live.webm(13.6초)와 세 화면 캡처에 있다.141–144에서 정상 runner로 각각185/121/120/121틱,48/41/40/41개 snapshot을 관찰했고 실제 키보드 이동과 controls.fire를 사용했다.네 시나리오 자체는 통과했으나 브라우저를 닫은 뒤 video.saveAs를 호출한 도구 오류로 최초 내보내기는 FAIL이었다.이미 완성된 원본 녹화 파일을 복사하고 실제 브라우저로 길이·해상도를 확인했으며 게임 시나리오를 반복하지 않았다.저장 순서를 수정했고 CI Canvas Roster10 job에서도 이 실제 영상 검사를 수행하도록 했다.
